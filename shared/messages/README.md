# 文案模板表

给青少年看的那一句话，**不是模型现场编的**。决策响应里的 `message` 只有
`template_id` 与 `params`（见 `server/app/contracts.py` 的 `Message`），正文在这里。

```
teen_v1.json（真源，手写）
  → scripts/sync_assets.py
  → app/assets/messages/          （随包发布）
  → app/lib/app/message_catalog.dart（端侧按 ID 查、填占位符）
```

**改动只改这个目录下的 JSON，不要改端侧代码。** 同步是单向的，`check_all.py` 的
「端侧 · 资产同步」会逐字节比对两份文件 —— 改了这里忘了跑同步，提交会被拦下来。

## 谁写

**传播学方向**。这是这份文件存在的全部理由：结论里的每个数来自规则引擎与决策模型，
但**怎么把结论说给一个十六岁的人听**是另一个专业的事。工程侧只负责让这句话
填得满、查得到、兜得住。

发出前请一并确认 `reviewed` 那一栏（见下）。

## 占位符契约

`{key}` 形式，只允许字母、数字、下划线，且必须以字母或下划线开头。
**一个模板里出现的每个占位符，服务端都得真的产出它** —— 这条由
`server/tests/test_messages.py` 对着实际响应逐条校验，不是靠自觉。

当前服务端可能产出的键：

| 占位符 | 含义 | 什么时候有 |
|---|---|---|
| `{total}` | 这一组的总次数 | 有 `message` 就一定有 |
| `{valid}` | 其中算数的次数 | 有 `message` 就一定有 |
| `{primary}` | 最该先改的那一处 | 有主问题时 |
| `{primary_count}` | 它在几次里出现过 | 有主问题时 |

`{primary}` 是**已经降过调**的措辞（服务端 taxonomy 给的「膝内扣」到端侧会变成
「膝内扣倾向」，见 `app/lib/app/fault_presentation.dart`），模板里直接用，
不要再加修饰词。

## 填不满就整句作废，不硬填

端侧遇到「模板里写了、`params` 里没有」的占位符时，**整句作废**，改用
`fallback_template_id`。理由不是洁癖：缺失的 `primary_count` 有明确含义 ——
组级统计里没有这个码。把它填成 0 就是在编一个「一次都没出现」的事实。

所以：

- **兜底模板只能用 `{total}` 与 `{valid}`。** 这两个是服务端无条件产出的，
  因此只要响应里有 `message`，兜底就填得满。兜底模板里出现别的键，
  等于把「填不满」这件事从一层传递到另一层。
- **`fallback_template_id` 指向的那条必须真的在 `templates` 里。**
  端侧在**装载时**就检查这一条并直接抛错 —— 一个找不到的兜底等于没有兜底，
  那必须在启动时炸掉，而不是等到某个用户做完一组动作、服务端恰好给了一个
  端侧没有的模板时才暴露（那时界面上会少一整段话，而没有任何东西会报错）。

## 未知 template_id

服务端比包里的这份新时会出现：端侧查不到 ID → 走兜底模板 → 报告里同时给出
一条 `headlineUnavailable` 或兜底来源的说明。**不静默留空**，也不退化成
「服务端没给结论」—— 那两种读法都比实际情况严重。

## 评审状态

每条模板带一个 `reviewed`：

- `false`（**当前全部如此**）：报告页在那句话下面加一句「这句话的文案还在评审中」。
- `true`：那句话按已评审对待，不追加说明。

**缺 `reviewed` 时按未评审算。** 这是保守方向：多一句「文案尚为草稿」
比少一句好，而将来新增条目的人忘了写这一栏时，代价只是多一行小字。

传播学方向定稿后，把对应条目的 `reviewed` 改成 `true`，再跑一次
`python scripts/sync_assets.py`。

## 为什么深蹲只有 5 个错误码

taxonomy 里有 45 个码，而深蹲规则实际只产得出 5 个
（`app/test/app/fault_presentation_test.dart` 有一条「五个，不多不少」钉着它）。
**多写的模板永远不会被渲染** —— 死文案会腐烂，而没人会发现。
新增动作时再按那套规则新增模板。
