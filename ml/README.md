# 数据集与微调（M4 模块）

> 主责：新农大信管 ｜ 协作：HSE 顾问（微调配方）
> 目标：自建「青少年体测动作决策数据集」→ 微调 Laya → 温度校准 → 可复现的评测报告

## 为什么这块要最先启动

两个原因，都不是技术上的：

1. **数据申请需要人工审批，周期不可控。** Fitness-AQA 走 Google Form 申请，Fit3D 需要注册，
   这些环节卡住的代价是整条链路停摆。
2. **微调是必需项，不是加分项。** Laya 出厂状态的中文能力第三方实测仅 47.7%，
   且**错误回答的置信度高达 0.91** —— 不微调、不校准就上线，等于给用户一个
   自信地给出错误建议的系统。开源仓库 `chinese-laya` 已证明中文微调可把一致率
   从约 34% 提到 75%+，官方配方在免费 Kaggle 2×T4 上 4–5 小时可跑完。

### 已知的缺口

**公开的中文「体育教学动作规范 + 错误类型」标注数据集不存在。** 这意味着：

- 动作**标签体系**（错误码分类）要由团队自己定义 —— 这件事已经在
  `domain/src/vitalteen_domain/rules.py` 与 `exercises/squat.py` 里做完了
- 数据集的**原创性**是真实的，可以写进答辩材料：不是「用了别人的数据集」，
  而是「把多个来源的姿态数据转换成了统一的体测动作决策标注格式」

## 管线形态

```
公开数据集（关键点/视频）
        │
        ▼  [转换层] 统一到 BlazePose 33 点格式
        │            COCO 17 → 33 的映射见 domain/src/vitalteen_domain/landmarks.py
        ▼  [特征层] 复用 domain/ 的特征算子  ← 关键：必须与端侧用同一套实现
        │            shared/fixtures/ 保证 Python 与 Dart 一致
        ▼  [样本生成] 特征 → 文本化 state + choice/score/noul 问题
        │            格式：ids / target（概率分布）/ markers
        ▼  [训练] RLCD，参考配方 batch 2 / grad-accum 8 / max-len 1024 / 4 epochs
        ▼  [校准] 按 (问题类型, 选项数) 分组拟合温度
        ▼  [评测] 基线 / 微调 / 微调+校准 三栏对比（一致率 + ECE）
```

**必须复用 `domain/` 的特征算子，不要另写一份。** 训练期的特征与推理期的特征只要
有细微差异，模型准确率就会静默崩塌，而且不会有任何报错。这正是
`shared/fixtures/` 那套跨语言契约要防的事。

## Laya 的已知约束（设计训练集时必须遵守）

这些是评估产物，不是猜测，直接决定数据集的形状：

| 约束 | 后果 | 应对 |
|---|---|---|
| 选项数超过约 20 后准确率急剧下降 | 候选集不能大 | **错误类型 4–6 类、矫正方案 5–10 条** |
| 存在位置偏差（曾有「50 题 46 题选 A」的报告） | 候选顺序会影响结果 | **训练与推理都必须做选项乱序**，并记录随机种子 |
| `score` 原语最弱（SST-5 仅 0.372） | 严重度打分不稳 | 考虑用多个 `noul` 拆档替代单次 `score` |
| 中文出厂 ECE 0.314、错误答案置信度可达 0.91 | 置信度不可直接当门控 | **必须做温度校准**，校准后 ECE 目标 < 0.12 |
| 版本迭代快（两周十余个版本，字段名变更过） | 训练与推理环境易漂移 | 锁 PyPI 版本 + 锁 HF checkpoint revision |

## 交付物

- 青少年体测动作决策数据集（含来源清单、许可证文件、转换脚本）
- 微调后的权重 + 训练配置 + 完整训练日志
- 温度校准参数（按 `(qtype, option_count)` 分组）
- **可复现的评测报告**：一条命令跑出「基线 / 微调 / 微调+校准」三栏对比
- GPU 租用记录与成本明细（AutoDL 按小时计费，预算 200–500 元）

## 环境

训练依赖见 [requirements-train.txt](requirements-train.txt)。
**不要在本地开发环境安装**（2GB+ 且无 GPU），只在租用的 GPU 机器上装。

首次跑通后立刻用 `pip freeze` 生成 lock 文件并提交 —— Laya 的版本漂移会让
「同一个 checkpoint 在训练脚本与推理服务里行为不一致」，而这种不一致不报错，
只让效果变差，是本项目最难定位的一类问题。
