# public/data/ · 宏观数据集

把宏观数据集放在这里，文件名 **`macro-dataset.json`**。

**这个文件目前不存在，是刻意的。** 页面此时会显示「数据未接入」并说明要放什么 ——
本页面展示的是**外部公开统计数据**，不是本平台产生的结果，因此不预置任何示例数据。
一个编出来的数字在答辩现场经不起一句「这个数据哪来的」。

## 文件结构

```jsonc
{
  "schemaVersion": "1.0",

  // 出处：六项全部必填，缺任何一项都会被拒绝加载
  "provenance": {
    "title": "数据集正式名称",
    "publisher": "发布机构",
    "publishedYear": 2024,              // 发布年份，不是抓取年份
    "url": "https://…",                 // 能打开看到原始数据的地方，不是二手转载
    "license": "公开报告，引用需注明来源",
    "coverage": "2024 年全国 31 个省市自治区",
    "notes": "抽测样本，非全量"          // 可选，口径备注
  },

  "observations": [
    {
      "stage": "junior",                // 见下方学段取值
      "year": 2024,
      "region": "北京",                  // 可选。省略表示「全国汇总」
      "metrics": [
        {
          "code": "BMI",                // 指标代码，同一年同一学段内唯一
          "name": "体重指数达标率",
          "value": 0.62,                // rate 口径下必须在 0–1 之间
          "unit": "ratio",
          "kind": "rate",               // rate | mean | index
          "sampleSize": 12000           // 可选，但分省数据缺了它就无法合成全国值
        }
      ]
    }
  ]
}
```

## 学段取值

`primary-1-2`（小学一二年级）、`primary-3-4`、`primary-5-6`、`junior`（初中）、
`senior`（高中）、`college`（大学）。与《国家学生体质健康标准》的分组口径一致。

## 两条容易踩的规则

### `rate` 口径的值必须在 0–1 之间

把百分比写成 `85` 而不是 `0.85` 是这类数据最常见的录入错误，而图表会照画不误。
加载器会在入口就拦下它，并提示你除以 100。

### 只有分省数据、没有全国汇总时，需要样本量

系统**不会对各省直接求平均**。各省抽测样本量差异很大，未加权的平均等于假设
「北京和西藏权重相同」，得出的数字没有意义 —— 而它在图上看起来和真值一样。

所以要么提供一条 `region` 省略的全国汇总行，要么给每一行都带上 `sampleSize`
（此时按样本量加权，并在图注里注明）。

## 想先看看界面长什么样？

仓库里有一份 `macro-dataset.example.json`。把它复制过去即可预览四个视图：

```bash
cd web/public/data
cp macro-dataset.example.json macro-dataset.json
npm run dev    # 在 web/ 目录下
```

它的出处声明明确写着「示例数据、不是真实统计」，而**页面顶部会原样显示那份声明**
—— 所以不会有人误以为那是真实数据。数值也刻意取整，一眼能看出是占位。

**不要把它带进答辩材料。** 预览完直接删掉 `macro-dataset.json`，
页面就会回到「数据未接入」的诚实状态。

## 数据从哪来

需要团队自行确认。可选方向：

- 教育部《全国学生体质健康调研》结果公告（每五年一次）
- 《国家学生体质健康标准》年度实施情况报告
- 各省教育厅发布的本地数据

**确认时要留意的四个问题**：用哪一份、覆盖哪些年份与地区、可视化哪几个维度、
引用方式怎么写。见 `web/README.md`。
