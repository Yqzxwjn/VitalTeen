# app/ · Flutter 手机 App

**当前状态：打开是一个完整的应用。首次进入填一次「我的资料」，之后每次打开直接落在
一条四标签的底栏上（开始运动 / 历史记录 / 体态 / 我的）；**点一个动作先进它的预览页**
（会动的示意图 + 相位词），按「开始」才起来相机 —— 手机对着人拍，实时出计数与膝角，
每做完一个给一次反馈与一个参考分，做完一组整页换成一份中文报告，这一组同时记进
历史。连不上决策服务时，同一份报告由手机自己算出来 —— 报告顶部会说明来源。**

领域层与 Python 参考实现逐值对齐；Phase 0 的真机帧率验证已通过（19 fps、5 分钟无衰减）；
相机、界面、语音、参考分、决策请求组装、决策服务调用、断网本机判定与报告渲染都已接上。
**首页的动作清单 9 项全部能练**（深蹲、立定跳远、开合跳、跳绳、俯卧撑、仰卧起坐、
引体向上、平板支撑、坐位体前屈）。`ExerciseStatus` 里仍然留着 `reserved`，
**但现在一个成员都没有** —— 坐位体前屈正是当年那唯一一个预留项，它上线这一轮
就是把这个状态转成 `live`。留着它不是为了今天，而是下一个动作在做的时候它还会回来。

**预览是应用自己画的**（`lib/ui/exercise_preview.dart` 的简笔人形 + `lib/ui/preview_poses.dart`
的关节角表），不是打包的外部素材：能用的那几套动作动画 GIF 版权是 Gym visual 的，
版权干净的不是真人照片就是静止插画。自己画还换来一件别处买不到的事 —— **预览上那一拍
的名字就是相机页 HUD 上那一拍的名字**（`preview_poses.dart` 是照 `action_spec.dart` 的
`hudStateLabels` 抄的，`test/ui/exercise_preview_test.dart` 盯着这两个表别漂开）。
**已上线的九个动作跑的是同一条管线**（`lib/app/squat_session.dart` + `lib/app/squat_page.dart`），
差别全部收在 `lib/app/action_spec.dart` 的 `ActionSpec` 里：动作码、机位、怎么建定义、
HUD 的相位词、丢弃原因、站位建议。类名里带 Squat 是历史，它们现在能跑任何动作。
还没有做的：距离/成绩估算（**立定跳远只判动作规范性，测不出厘米成绩** —— 单目无世界
坐标，见 `docs/domain-layer-design.md` 附录 A）、立定跳远的纠正方案库（报告里暂时没有
「纠正方案」一节，不报错）、器材选择界面（判定暂时一律按徒手算）、L1/L2 滤波接线、
多人入镜时选取最大包围盒、身高体重的任何消费（开发计划 Phase 1 末尾有一份「尚未做的」
清单，这份与那份是同一批东西）、**「体态」页判得了什么**（它只看两条绑了真实故障码的
倾向；「脊柱侧弯」没有对应的量，页面上正面写清了这一点，见「[体态](#体态)」。这些量
**从本版本起才开始记录**，更早的练习补不回来）、四张插图本身（**版式与图位已经就位**，见
「[插图位](#插图位)」）、历史的导出与云同步（**历史只在这台设备上**，与资料同一条边界）。

**`platform/` 是唯一允许 import 插件的地方。** 领域层不认识 `PoseLandmarkType`，
也不认识 `InputImage`；`app/` 与 `ui/` 不认识 `CameraController`。
将来换姿态后端时，改动被限制在 `platform/` 一层。两条存储通道（资料与历史）也守
同一条规矩：`app/` 里只有「存的是什么」，字符串怎么过通道是 `platform/` 的事。

**网络也守同一条规矩**：唯一一处 HTTP 调用是 `platform/decide_client.dart`，
`app/` 里只有「发到哪儿、失败了该说什么」这些纯数据。所以「每种失败怎么说」
能在主机上穷尽测试 —— 而它恰好是最容易写错的部分。

## 界面

界面是一条**设计令牌**走到底的：颜色、间距、圆角、文本样式与动效曲线全在
`lib/ui/design.dart`，页面里不再出现 `EdgeInsets.all(14)`、`fontSize: 19` 这类
随手写的值。改动一次令牌，四个标签页一起变。

几条立住的规矩：

- **背景只有实色。** 首页横幅、等级徽章、动作图位都不用渐变。唯一的例外是
  相机画面上那层压暗渐变（`squat_page.dart` 的 `_Scrim`）—— 它压的是实时画面，
  换成实色会把画面挡死。
- **字号落在固定几档上。** 12/14/16/18/20/24/30/36/48，每个都对应一个有名有姓的
  文本样式（Heading / Title / Body / Button / Caption），代码里按名字取。
- **图标自绘。** `lib/ui/app_icons.dart` 按 24 网格、1.6 笔画重画了导航、分区与
  操作行要用的那一套；相机 HUD 与报告页仍用 Material 的功能性小图标。
- **字体不换。** 应用里九成是汉字，Geist / Manrope 这些西文字体没有汉字字形。
  身份由字阶、字重、字距与颜色建立，字体回退链见 `kCjkFallback`。
- **组件级文本样式要从主题的正文样式上长出来。** `ThemeData.fontFamilyFallback`
  只作用于 `TextTheme`；AppBar 标题、按钮文字是整份替换的样式，所以 `theme.dart`
  里用 `_component()` 保留字体族 —— 漏了会出现「正文正常、按钮里的字变方块」。

改版后的界面快照与说明在 [../docs/ui-redesign/](../docs/ui-redesign/)。

### 连不上服务时，本机算一份

测试者手里没有你笔记本上跑着的服务。所以「分析这一组」有两条路：

| 服务端的状态 | 走哪条 |
|---|---|
| 答了，是个决策响应 | 用它的结论（`ReportOrigin.server`） |
| **没答话**（连不上、超时） | 本机用同一套规则算一份（`ReportOrigin.device`） |
| 答了，但答的是失败（401 / 400 / 404 / 5xx / 正文读不懂） | **照旧失败**，不兜底 |
| 随包的文案表或方案库读不出来 | 报「本机缺件」—— 那是打包问题，要重装 |

第三条线画在**「有没有拿到答复」**上，不是「失败得严不严重」。理由写在
`decision_submission.dart` 的 `DeviceFallbackCause` 上：服务端答复了还转本机，
会让「密钥配错」「两端契约不一致」「地址填错」永远查不出来 ——
现场表现为「一直有报告」，而报告不是服务端给的。

**本机算的与服务端算的必须逐字段相同**，否则测试者报回来的结论没法与联网时比较。
两把锁钉住这一点：

- 数值常量 → `shared/decision/rule_settings.json`（导出 + 同步 + `--check`）；
- 行为与文案 → `shared/fixtures/decision_response_conformance.json` 的 13 个场景，
  端侧拿同一份请求跑 `decideLocally`，与 `expected_response` 深比较
  （`test/app/local_decision_conformance_test.dart`）—— **唯一允许的差异是
  `meta.latency_ms`**，本机没有网络往返可测。

报告自己会说清楚来源，而且**在两个位置**：

- **报告顶部一行**（`DecisionReport.originNotice`）：「本机判定 · 当时连不上决策服务」。
  它必须在读第一个字之前就被看见 —— 小结、参考分、建议练习都排在它后面，
  等滚到底才知道这份是谁算的就晚了。
- **末尾声明区**（`DisclosureKind.decidedOnDevice`）把同一件事说完：用的规则与服务端
  相同，但结论不是服务端给出的。这里不是折叠区。

其余按来源分支的措辞：「原始数据」里的标签换成「本机生成的响应」，参考分换成
「本机判定参考分」，耗时那句不再引用服务端自报的毫秒数（本机来源时它是占位的 0）。
**不加新的 `AnalysisResult` 子类** —— 界面渲染方式完全相同，多一条 switch 分支
收益为零，而漏掉一条就是报告在撒谎；来源是报告**内容**的一部分，所以它是
`DecisionReport` 的字段，措辞集中在 `decision_report.dart`，widget 只管排版。

Python 与 Dart 的舍入不一样（`round()` 半偶 vs 半远离零，`f"{x:.2f}"` vs
`toStringAsFixed`）：差异只在一半的 `.5` 上，**不报错**，只会让分数偶尔差 1 分。
`python_math.dart` 把三个函数逐位复刻，并由 fixture 里那几个二进制精确值钉住。

## 跑起来

```bash
flutter analyze && flutter test     # 静态检查 + 全部回归

# 真机（必须 release：debug 下帧率没有参考价值）
flutter build apk --release --target-platform android-arm64
adb install -r build/app/outputs/flutter-apk/app-release.apk
adb shell am start -n cn.vitalteen.vitalteen_app/.MainActivity

# 或者从仓库根目录一条命令跑完全部套件：
python scripts/check_all.py
```

**`--target-platform android-arm64` 别省。** 依赖里的 `jni` 有 native 代码，
不加这个参数会对三个 ABI 各编一遍，而演示机就是 arm64-v8a —— 省掉的三分之二纯属白干。

**release 包启动即崩、而且没有任何 Dart 日志？** 十有八九是 R8 把 ML Kit 带进来的
WorkManager 裁掉了一半 —— 崩在 ContentProvider 初始化阶段，Dart 引擎还没起来，
所以查不到任何应用层输出。成因、修法与排查顺序都写在
`android/app/proguard-rules.pro` 的注释里，**不要靠猜**。
（debug 构建不做裁剪，所以这个坑只在打正式包时才出现。）

**开屏那张图在 Flutter 起来之前就已经在屏幕上了。** 引擎启动那段时间由 Android
的启动窗口顶着（`android/app/src/main/res/drawable/launch_background.xml`），
而它放的就是同一张图 —— 真机上 debug 包这段是 **2.7 秒**，原先那里是一张纯白，
看起来就是「装坏了」。所以 `SplashPage` 自己**不再淡入**：同一个画面淡入两次，
中间会闪过一片白。两份图的同步由 `test/ui/brand_assets_test.dart` 逐字节守着，
替换步骤见 [docs/brand-assets.md](../docs/brand-assets.md)。

开屏是**一次性**的：等满就走，不停留、不循环。**不要给它加循环或常驻动画** ——
`pumpAndSettle` 会永远等不到静止，界面测试只能靠超时失败，而那是这一屏唯一能被
自动验证的部分（`splash_page.dart` 与 `squat_widgets_test.dart` 里各写了一遍理由）。
反过来也要注意：它现在等的是一个 `Timer`，而等它的那段时间里**没有帧要画**，
所以测试里不能只 `pumpAndSettle`（会立刻返回），要显式 `pump` 过时长。

**欢迎页已经删掉**（2026-10-06）。它原来只说两件事 —— 这个应用要你干什么
（站好 → 标定 → 开始做），以及**画面去哪了**（「画面不出手机。动作识别全部在这台
设备上算完，视频不会被保存，也不会上传。」）—— 而两件事都得为一次「开始」按钮
付出一整屏，用户每次打开都得多点一下。现在：

- 三步说明挪进「我的 → 关于」（`kHowItWorksSteps`，`me_page.dart`）；
- 隐私那段**落在资料表单最底下**（`PrivacyNote`，与「关于」共用一份）。这条不能只
  写在隐私政策里：用户把镜头对准自己之前有权知道，而资料页是首次打开唯一必经的一屏。

**「我的资料」只在本地没有档案时才拦人**，它是首屏，也是唯一能改「跟谁比」的地方。
资料在「我的」那一页与首页横幅那一行上看得见。见下面的「[我的资料](#我的资料)」。

**「外壳」是一条四标签的底栏**（开始运动 / 历史记录 / 体态 / 我的），从开屏之后一直挂着，
直到进预览页为止。标签怎么切、历史怎么存，见下面的「[四个标签](#四个标签)」；
四处插图位怎么换图，见「[插图位](#插图位)」。

**预览页与练习页不在外壳里。** 它们是整屏替换掉外壳的两屏，所以「练习页盖住底栏」
是结构性的 —— 那一屏里外壳**根本不在树上**，而不是「底栏被藏起来了」。这不是排版
偏好：`pose_camera_pipeline.dart` 顶上写着相机控制器不能绑死在某个 `State` 的生命周期上，
而外壳用的 `IndexedStack` 会把四个标签的 `State` 一起养着（这正是它换来的好处：
清单滚到一半切走再回来还停在原地）。

六屏之间用 `_stage` 换页面，**不立路由栈**（`main.dart` 顶上写了为什么不立）。
返回键的去向由同一处 `PopScope` 决定 —— **`canPop` 与「按下去做什么」读的是同一个
`_backTarget`**，写成两条独立的 switch 时迟早有一处漏改，表现是「按返回键没反应」。
契约是：

| 在哪一屏 | 系统返回键 | 页内出口 |
|---|---|---|
| 启动 / 欢迎 | 退出应用 | — |
| 我的资料（**首次**） | 退出应用（诚实：不填就是不想用） | 无取消按钮 |
| 我的资料（从「我的」进来改） | 回「我的」，丢弃改动 | AppBar 返回 + 取消 |
| 外壳 ·「开始运动」 | 退出应用 | — |
| 外壳 ·「历史记录」/「体态」/「我的」 | 切回「开始运动」 | — |
| 预览页（**9 项都进得来**） | 回「开始运动」 | AppBar 返回 |
| 练习页（相机态与报告态**都是这条**） | 回「开始运动」 | AppBar 返回，tooltip「返回动作列表」 |

三个普通标签上按返回**回的是「开始运动」，不是上一个待过的标签** —— 那是路由栈的语义，
这个应用不用它（见 `main.dart` 顶上）。这三个去向由 `app_shell_test.dart` 一条条钉住。

一组做到一半按返回也**直接丢弃，没有确认框** —— 加确认框是合理的后续项，不在这一版。
两个出口（AppBar 那个按钮与系统返回键）机制不同 —— 前者走 `SquatPage.onExit`，后者走
`PopScope` —— 但**落在同一个去向**（`_goShell(_Tab.workout)`），所以不会各走各的。

**从哪儿来回哪儿去**：从「我的」去编辑资料，保存之后落回「我的」；首次填写（从开屏
直接进来，那时还没有档案）保存之后落「开始运动」—— 他是一路走向训练的，落「我的」
会让他迎面看到自己刚填的那张脸，还得自己找路去练。区别只藏在一个事实上：
**进资料页之前这台设备有没有档案**，所以 `_onProfileSaved` 是**先问再写**的
（写完再问就永远得到「编辑」一个答案）。

## 四个标签

开屏之后是一个四标签的外壳：**开始运动**（打卡卡 + 那张动作清单）、**历史记录**、**体态**、
**我的**（头像 + 等级卡 + 资料 + 三个入口）。四个标签各有自己的 `Scaffold` 与 `AppBar`（嵌套 Scaffold）—— `ScaffoldMessenger`
只在最外层那个 `Scaffold` 上显示 SnackBar；外层有 `bottomNavigationBar` 时 body 的
MediaQuery 会去掉底部内边距，内层 `SafeArea` 不会重复垫；`NavigationBar` 自己包了
`SafeArea`，底部安全区不用我们管。

**用 `IndexedStack` 而不是条件构建**：四个标签的 `Element` 一直挂着，`ScrollPosition`
因此天然保留 —— 用户在动作清单里翻了半天，去「我的」看一眼再回来，不会被弹回顶部。
**不用 `PageView`**：它带来横滑手势（产品没要，还会与将来的列表手势打架），默认还会
dispose 离屏页，要留状态就得给每页套 `AutomaticKeepAliveClientMixin`。

**代价是 `IndexedStack` 不包 `TickerMode`** —— 未选中那三页里的 Ticker 照跑。现在四个
标签都没有常驻动画，看不出差别，但 `exercise_preview.dart` 里就有一个 `repeat()` 的
现成例子，而这份清单会继续长。所以这一层自己包了一层 `TickerMode(enabled: i == index)`，
`app_shell_test.dart` 里有一条读 `TickerMode.valuesOf` 钉住它 —— 断的是**这个值报了
false**，不是「代码里写了那个单词」。

**底栏那四个标签的文字要限定在 `NavigationBar` 里找**（测试里也是这么写的）：
「历史记录」与历史页的标题、正文都可能重字，不限定的话 `find.text` 会一次找到两个。

**顺序在三处各写了一遍**（`_Tab` 枚举、`IndexedStack.children`、`NavigationBar.destinations`），
而它们对不上**不会报任何错** —— 只是点击切到隔壁那一页。所以加标签要三处一起加，
`app_shell_test.dart` 里那份标签清单是唯一的守卫。

### 历史记录

一条记录是 `lib/app/session_record.dart` 的 `SessionRecord`：动作码、**当时的**动作名、
本组结束的挂钟时间、次数、是不是计时制、可空的姿势分、是不是暂定。动作名冗余存一份 ——
将来动作改名或下架，旧记录不至于变成一行空白。

存在一条**新开的原生通道**上（`vitalteen/history`，与资料共用同一个 prefs 文件，各占一个键）：
一个通道一件事，而且两份数据的形状本来不同源（资料是「一份对象反复改写」，历史是
「一列事实往后追加」），合成一条会让两个能力的测试互相牵制。

**写入时机在 `set_recorder.dart`，挂在会话的 `finished` 相位上，不挂在「结束本组」
那个按钮上**：十秒无动作的自动结束是会话层在 `feed()` 里判的，按钮根本不会被按到 ——
而它恰好是「用户放下手机走开」的那一次，也就是最该记下来的那一次。相位 `finished`
是会话层唯一一次说出「这一组完了」的地方，两条结束路径都会经过它。

**封顶 200 条**（一天一组约半年，一天三组约两个月）。不封顶的代价是三条一起出现：
保存是全量重写（`SharedPreferences` 的 `commit()` 把整个 XML 写一遍）→ 每组结束的
写盘量无界；Android 把整个 prefs 缓存在进程内存里 → 基线内存无界；单点损坏的代价是
**全部**记录。

**写不进去要说，而且不动内存里那份。** 这一条与资料刻意相反（资料写失败必须留在内存里，
否则用户刚填完的东西转眼就没了）：历史是**日志** —— 在内存里补一条、下次打开又没了，
会让「历史」这个词变成假的。所以那条路上只有两种结局：真的存下来了，或者弹一条
「这一组没能存到这台设备上，历史记录里不会出现。」（这句话全部的信息量就是「不怪你」：
不说的话，用户会怀疑是自己没练对。）

**读失败 == 空表**（与资料同一条契约，代价不同）：读不出来时历史页会说「还没有练习记录」，
那一刻这句话可能是假的 —— 但对一个只读的页面这是安全方向，它不会误删任何东西。

**读盘的时机有两处**，都在 `main.dart`：每次**进壳**一次（从练习页回来那一刻必须
看见刚写进去的那条），以及每次**切到「历史记录」或「体态」标签**一次。**没有第三处** ——
「开机读一次」是多余的：进壳只有 `_goShell` 一条路（首填保存、档案已存在时按「开始」、
从练习页/预览页返回，都走它），而那一条已经在读了。

第二处是在补一个竞态：写入是异步的（练习页刻意不 await，界面不等盘），进壳那一次
重读可能赶在写落盘之前 —— 窗口只有几毫秒，而赌输一次的代价正是这两个功能存在的理由
（用户练完一组，历史里却说没有，而且在旧口径下它不会自己变回来）。**「体态」与
「历史记录」是同一条理由，不是第二个口子**：它吃的就是同一列记录。

并发读用 `_historyEpoch` 兜住：先发起的那次可能后回来，不能让它用旧表盖新表。

汇总（总次数 / 平均姿势分 / 连续天数）在 `lib/app/history.dart`，纯函数、单测穷尽：

- **总次数是记录条数，不是把次数加起来** —— 深蹲 12 个与立定跳远 5 段不能相加。
- **没有分数的记录既不算 0、也不进分母**（`score` 是可空的：一个 rep 都没打上分时它
  就是 `null`）。0 是一个真实的低分，不是「没有分」。一条有分的都没有时显示「—」，
  而连续天数那里一个真的 0 就写 0。
- **连续天数从今天往回数，今天还没练不算断**（从昨天起数）—— 早上打开应用时不该
  突然变成 0。日期加减用 `DateTime(y, m, d - 1)`，**不用 `subtract(Duration(days: 1))`**：
  DST 地区的一天不是 24 小时。
- 界面 `build` 里 `DateTime.now()` **只取一次**再传下去 —— 每个数字各取一次的话，
  跨零点那一刻会分裂出两个「今天」。

历史页上的分数**用的是中性色，没上红绿**：`scoreColor` 要一个 `FormRating`，而评级
要那张阈值表，`SessionRecord` 里没存。猜一个评级就是在报一个数据支撑不了的判断。

**记录格式升到 v2，多一个 `fault_counts`**（组里哪些故障码各命中了几个 rep）。加它是
为了让「体态」那一页有跨时间的量可看 —— 在这之前，会话里算出来的膝角、躯干前倾、左右
对称全都在写盘那一刻丢掉了。字段**可空，而可空这件事有两层含义**：

| 内存里 | 含义 |
|---|---|
| `null` | 这一版之前写的：**没采集过这个量** |
| `{}` | 采集到了，**这一组一个 rep 都没命中** |

`null` 与 `{}` **必须分得开**：折平之后，体态页会把「不知道」当成「很干净」，把一批
老记录算进分母，结论被系统性压低 —— 而页面看上去一切正常。

**v2 的解码必须接受 `fault_counts: null`，这一条是灾难防线而不是洁癖。**
`platform/history_store.dart` 的 `appendSessionRecord` 每次落盘都是「整列解码 → 整列
重编码写回」，于是**下一次练完一组**，所有 v1 记录会被读进内存、再当作 v2 写回去。
解码端只要拒收那个 `null`（一个看起来更「严格」的写法），那一次回写就把用户的全部
历史变成读不回来的字节。`session_record_test.dart` 与 `history_store_test.dart` 各有
一条用手写 v1 原文跑的往返测试钉住它。

存的是**全量** `faultStats`，不是 `scorableFaults`：阈值表 74 条全是 `pending_review`，
`scorable` 现在恒为 false，只存可扣分的等于一条都不存。

## 体态

「体态」页把练习记录里**反复出现**的动作特征汇总出来，再给一组矫正练习。它是纯读的，
数据源就是历史那一列 —— 没有自己的存储，也没有写入路径。

**只有两条倾向，每一条都绑一个真实存在的故障码，而且只在这个码真能产生的动作上统计**：

| 标题 | 通俗说法 | 依据的故障码 | 算在哪些动作上 |
|---|---|---|---|
| 上身前倾倾向 | 「圆背」「驼背」 | `EXCESSIVE_TRUNK_LEAN` | `SQUAT` |
| 左右用力不均倾向 | 「左右不平衡」 | `ASYMMETRY` | `SQUAT` |

这张表在 `lib/app/posture_analysis.dart`，**由测试对着 `kActionSpecs` 的真实规则集
机械校验**（谁加了新规则、改了码名而没回来维护它，测试会红）—— 手写的表必然漂移，
而漂移的后果是页面拿一个永远算不出来的码做分析，结论永远是空的且不报错。

**「脊柱侧弯」不产出任何结论**，这不是措辞保守，是**没有数**：全仓没有额状面肩线/
髋线水平差的特征，唯一的左右量 `knee_symmetry` 要在侧拍画面里读，而深蹲默认侧拍，
两条腿在画面里几乎重叠。替代做法是在页面的固定声明块里**正面写清「这一页判不了它」
并给出物理原因** —— 不写的话，用户会拿「这里没提」当成「这里没查出来问题」。

**分母是这一页最容易做错的地方，「几组里几组出现」里的分母不是「练了多少组」**：
它要求这一组记了故障计数（`faultCounts != null`）、动作真能产出这个码、且落在 30 天
窗口内。少任何一条都会让出现率系统性失真，而失真不会报错。

**什么时候不说话，与说了什么一样重要**：低于 6 组不出结论（页面转说「再练 N 组」）；
够多了但一组都没命中也**不塞一张 0% 的卡**（那会被读成「这条也查过、你有」）。
四种情形各有各的话，`test/ui/posture_page_test.dart` 一条条钉住。

**建议练习按故障码查方案库**（`PlanCatalog.selectForFaults`），器材一律按「什么都没有」
筛 —— 这一页不知道用户手边有什么，而推荐一个他做不了的动作比不推荐更糟。**方案库读不
出来只把建议那一段降级成一句实话，不影响上面的倾向结论** —— 与练习页「读不出方案库就
整份报告不出」刻意不同：那边整份报告是一体的，这边倾向才是主体，建议只是附加。
方案库里现在一条已核定的都没有，所以整段会走 `selectForFaults` 的回退路径，
**`includesUnreviewed` 那个位不能丢**，否则等于把草稿冒充成核定过的处方。

## 动作预览

首页每一张卡都点得动，**点进去先看到的不是相机，是这个动作的示意图**。这一屏要解决的
是「卡片上那一句话说不清的事」：立定跳远的预蹲要摆臂、平板支撑是前臂撑地、
坐位体前屈折的是腰不是膝 —— 一句话说不清，说了也未必有人读。而站到镜头前那一刻
已经在花掉一次站位和一次标定了，来不及再解释。

**已经上线的动作**在这一屏上有「开始」，按下去才起来相机。**还没做的那三个**也进得来，
但那一格换成一句实话（「这个动作还没做…」）——**不给一个置灰的「开始」**：置灰的按钮
看起来像「你现在的状态不对，弄好就能点」，而实际上这个功能根本不存在。

**图是应用自己画的**，不是打包的素材。试过外部素材，能用的那几套 GIF 版权是
Gym visual 的（仓库里白纸黑字写着复制仓库不等于拿到授权），版权干净的不是真人照片
就是静止插画，而且都没有立定跳远。自己画换来三件事：每一拍的相位词可以用**引擎真正
在判的那几个词**（`preview_poses.dart` 照 `action_spec.dart` 的 `hudStateLabels` 抄，
`test/ui/exercise_preview_test.dart` 有一条盯着这两个表别漂开）、**仓库里没有一份外部
素材**、离线可用。

画法是**关节角 → 前向运动学 → 二维点**（角度约定写在 `preview_poses.dart` 顶上）。
好处是肢体长度恒定，不会画出「大腿变长了」；代价是它是**二维**的：正视图画不出屈膝
（那是深度），侧视图画不出分腿。所以每个动作挑一个视角，而且那个视角必须能把它最
重要的幅度摆出来 —— 只有开合跳用正视，因为它的全部看点就是两腿分开多大。

**这张表是给人看的海报，不是判定依据。** 它和领域层没有关系，谁也不驱动谁。
它的九个动作**现在全都有领域定义了**（坐位体前屈做出来之前，它是表里唯一一个
只有姿势、没有定义的动作）—— 而这件事本来就是对的：**两张表各自独立才是常态**，
预览回答的是「这个动作长什么样」，不是「引擎怎么判它」。

`ExercisePreview` **有一个永不停止的动画**（`..repeat()`），所以界面测试里不能用
`pumpAndSettle`（会一直等下去），要用 `pump(Duration)`。

## 插图位

界面上有五个插图位：**首页顶部横幅、每张动作卡片的图标、历史页的空状态、「体态」页的
空状态、「我的」页的头像**。这一轮**只搭了版式，图位留空**（版式先行），五处各自落在
一个兜底上 —— 卡片上是那个动作自己的简笔人形，其余四处是品牌色的图形。界面是完整的、
不难看的，所以那五张图是加分项，不是缺件。

机制在 `lib/ui/illustration_slot.dart`：`Image.asset` + `errorBuilder` —— 文件不在就画
兜底，文件在就画图，于是同一个控件既是占位又是成品。**把图丢进 `app/assets/images/`
即生效，不用改一行代码**（`pubspec.yaml` 已经整目录声明了，加文件不必动它；
但要重新打包，热重载不够）。

卡片上的兜底不是通用图标，是**那个动作自己的**简笔人形：`preview_poses.dart` 的
`kPreviewThumbnailIndex` 显式写死每个动作取第几拍，**不用「中间那一拍」那种启发式** ——
平板支撑只有两拍，中间那拍是「没在撑」（站着的人），拿它当缩略图正好是错的。
`illustration_slot_test.dart` 里有一条逐码检查「那一拍不是默认站姿」，抓的就是它。

**未开放的动作没有图位**（继续用灰色图标）：图位是「能用」的视觉语言，借过来的话
用户会以为它快要能练了。**现在没有这种动作**（见文件头），这条规矩跟着
`ExerciseStatus.reserved` 一起留着。

交付给做图的人的需求单（文件名、目标像素、每个位置画什么）在
[docs/brand-assets.md](../docs/brand-assets.md)。**「丢进去即生效」这件事是实测过的**：
往目录里放了四个同名的假文件再跑一遍界面测试，268 条全绿 —— 而那次实测当场抓出了
一处会红的地方，所以那条经验也写进了那份文档。

## 我的资料

一次性填这几项：**头像、昵称、性别、年龄、年级、身高、体重**。存在这台设备上
（`SharedPreferences`，走 `vitalteen/profile` 原生通道，**没有引任何存储插件** ——
理由与 `vitalteen/display` / `vitalteen/speech` 那两条一样，见 `MainActivity.kt`），
之后每次打开直接用。

**国标组别不再手填，按年龄与性别自动分**（`standardGroupFor`，2026-10-06 改）。
原来那一项是个自由文本框，填错了没人拦得住 —— 而它决定「跟谁的标准比」。现在
年龄 + 性别一变，表单上那行提示就跟着变（「国标组别：高中男子（按年龄与性别自动分，
不用自己选）」），用户看得见系统把它读成了什么。分档按《国家学生体质健康标准》的学段：
小学一二年级 / 三四年级 / 五六年级 / 初中 / 高中 / 大学，后面接「男子 / 女子」。
**年龄是近似**（入学早晚差一岁），但这一项比自己选错一档要轻，而且随时能在「我的资料」里
改年龄重算。

**头像在这一页就能选**（2026-10-06 加）。它是首次打开的必经一屏，而头像是「这是我的
应用」最直接的一步 —— 之前只有「我的」页能换，第一次进来的人看到的是一张首字母底图。
头像本身**不进 `Profile`**：它是一张文件，由 `avatar_store.dart` 走 `vitalteen/avatar`
通道管，与那份 JSON 各存各的（`app/profile.dart` 里不出现路径）。

昵称**允许空着**（空是「还没填」，不是错误）：应用里凡是需要称呼他的地方都用
`profileDisplayName(profile)` —— 填了就喊昵称，没填就喊「同学」。空着一块不写，
看着像出了错。

| 这份资料影响什么 | 不影响什么 |
|---|---|
| 组末分析表单的预填（**不含昵称**，前四项从性别起） | **身高体重：只做记录。** 全仓库没有任何代码消费它们 —— 不进决策请求、不参与判定、不算 BMI |
| 称呼：首页横幅的问候语、「我的」页头像的首字 | 相机、计数、参考分、语音：一个字都不读它 |
| 「我的」页与首页横幅上那一行摘要 | 服务端地址：**仍然不落盘**，与资料不是一回事 |

**档案格式升过一次版（v1 → v2，为了加昵称），解码器同时认两个版本。**
版本号的判据从「不相等就丢」改成了「认识的就收」：v1 的档案里没有 `nickname`
这个键，按空串读进来 —— 用户填过的身高体重一个字都不丢，只是昵称那栏空着等他补。
**这条必须与 `profileSchemaVersion` 一起改**：只改常量不改解码器，现有用户的资料会在
下一次启动时静默消失（`decode` 返回 `null` ＝当作没填过，应用会再问一次，而用户填完
也不知道刚才发生了什么）。`test/app/profile_test.dart` 里那条「v1 的 JSON 读进来，
昵称是空串、其余六项一个不差」就是替他看着的。

**档案唯一的写入者是「我的资料」页那个「保存」按钮。** 在组末分析面板里改年龄只影响
当次分析、**绝不写回档案** —— 面板里那句「在这里改动只影响这一次分析」是字面意思，
`analysis_panel_test.dart` 里有一条测试专门盯着「面板从没碰过存储」。

**为什么可以持久化。** 早先的规则是不持久化，理由是：

> 一个上次留下的年龄看起来像是「已经确认过」

这条意见是对的，所以持久化必须**不制造那个假象** —— 下面五条是答它，不是绕开它：

1. **有地方看得见**（「女 · 16 岁 · 高一 · 高中女子」）：首页横幅上那一行每次打开都在，
   完整的一份在「我的」标签上，而不是藏进表单当一个来路不明的默认值。
   **首页那一行不能删** —— 早先那份还有一个自己的卡片，改版后压成了横幅上的一行，
   它是这条承诺唯一还看得见的地方（`home_page_test.dart` 与 `squat_widgets_test.dart`
   各断了一遍）；
2. 预填时带**出处与日期**：「已按「我的资料」填好（更新于 2026-10-04）」；
3. 面板里的改动**不写回**（上面那条）；
4. 资料满一年时**提示复核**（「我的」页上那行橙字，点得动，直接去编辑）——
   一年必然至少长一岁。**绝不自动加年龄**，那是编数据；
5. 保存失败要**说出来**（SnackBar「资料没能存到这台设备上，下次会再问一次」），
   内存里那份照常用 —— 与语音「引擎说不出中文就弹一条」是同一条原则：
   宁可说出坏了，也不假装成功。

档案的编解码在 `lib/app/profile.dart`（纯 Dart，主机可测）；`lib/platform/profile_store.dart`
只负责把一个 `String?` 搬过通道，不认识里面的格式。**任何损坏的档案都解码成 `null`**，
退化成「再问一次」，绝不让应用打不开 —— 六类损坏输入（非 JSON / 缺字段 / 版本号不对 /
年龄越界 / 体重 NaN …）全部有测试。

## 打卡、连胜与等级

**全部从已有的练习记录里算出来，没有第二份存储。** 存的东西一样都还是 `SessionRecord`
（`history_store.dart` 那条通道），打卡、连胜、等级、每日任务都是它的纯函数投影
（`lib/app/growth.dart`）。这样就不会出现「记录写了、打卡没写」这种半截状态。

| 概念 | 定义 | 在哪看得见 |
|---|---|---|
| 打卡日 | 那天练过至少一组（按**本地日历日**） | 成长页那 4×7 个格子 |
| 当前连胜 | 从今天往回连续打卡的天数。**今天还没练不算断** —— 今天还没过完 | 首页那张卡的「连续打卡 N 天」 |
| 最长连胜 | 历史最长的那一段 | 成长页「累计」 |
| 等级 | **由连胜决定**，七档：起步(0) / 活力新星(2) / 坚持之星(5) / 训练达人(10) / 自律高手(21) / 硬核少年(45) / 传奇(90) | 首页卡右上、「我的」那张卡、成长页顶上 |
| 成长值 | 每组 10 点，平均分每满 10 分再加 1 点。**连胜断了不清零** | 成长页 |
| 今日任务 | 三条：练 1 组 / 练到 2 个不同动作 / 有一组 80 分以上 | 首页卡的进度条、成长页清单 |
| 成就 | 八枚：第一组 / 连练 3、7、30 天 / 练满 10、50 组 / 六项动作 / 一次 90 分 | 成长页「成就」那张卡（没拿到的显示「怎么拿到」） |

**为什么等级挂在连胜上、而不是成长值上。** 连胜是这一个应用里唯一**会自己归零**的数，
等级跟着它才有压力；成长值是另一件事（累计的努力），它只涨不跌。断了连胜就把等级
一起抹掉，人会连练习也不想开；反过来把等级挂在成长值上，「连胜」就只剩一个装饰性的数字。
两个数分开显示，各说各的 —— 「再连练 N 天升到 Lv.x」那句只讲连胜。

**入口有两个**：首页横幅下面那张卡（点它进成长页），以及「我的」页头像下面那张等级卡
（同一个去处）。成长页是 `_Stage.growth`，与预览页、练习页一样是**整屏替换外壳**的一屏，
不立路由栈（`main.dart` 顶上那条规矩）；系统返回键回「开始运动」。

**它不改判定。** 等级与任务只影响首页与成长页上的显示，不进决策请求、不影响参考分、
不写进 `SessionRecord`。今日任务那三条门槛（1 组 / 2 个动作 / 80 分）是**产品数值**，
不是体育阈值 —— 所以它们写在 `growth.dart` 里，**不进 `shared/thresholds/`**
（那条规矩管的是「决定判定的数」）。

**成就也一样不落盘**：拿没拿到是每次从记录里现算的（`achievementsOf`）。存一份
「拿过什么」看起来更省事，但删掉记录之后徽章还亮着 —— 两个真相源迟早会打架，而这一个
没有维护成本。图标**不在 `growth.dart` 里**：`IconData` 是 material 的东西，
那一层到 `foundation` 为止，界面按 `id` 去查图标表（`growth_page.dart` 的 `_badgeIcon`）。

## 一次深蹲的流程

1. **自检**：画面里有人、全身入镜、距离合适、站成 45°。四项都过才放行。
2. **标定**：站直不动约 15 帧，采一份站立基线。个体化阈值都从它算。
3. **计数**：状态机跟着下蹲—起身走，数到一次就出一张反馈卡与一次参考分。
4. **本组结束**：站直不动 10 秒自动收工（也可以按按钮）。此时**整页换成报告**，
   相机同时停掉 —— 见下面「[一组做完之后](#一组做完之后)」。
   底部两个出口是「再来一组」（**保留标定**，同一个人不用再站一次）与「重新标定」。

## 立定跳远

同一页、同一条流程，几点不同：

- **机位还是 45°，而且这次它不是「选得好」而是「必须」。** 立定跳远的
  `heel_rise_ratio_L` 声明 `views: [sagittal, oblique45]`，正视机位下
  `Calibrator.feed` 永远拿不到第五个必需特征 —— 表现是标定条卡住不动、
  **不报任何错**。拦住这件事的是首页那道站位门禁，而它拦得住的理由恰好是
  **门禁看的是画面上量出来的侧向比，不是任何一个人填的机位**：正对镜头的人
  在特征上和 45° 的人算出来一模一样（`slj_session_test.dart` 里有一组测试
  把这个「一模一样」也断言了），所以除了这道门禁，没有第二处能拦住他。
- **相位词不同**：站立 / 预蹲 / 蹬伸 / 腾空 / 落地缓冲（`sljHudStateLabels`）。
- **丢弃的原因不同**：括号里写的是「没跳到落地缓冲，或动作被打断」——
  深蹲那句「幅度不够」在立定跳远上是错的，它丢的那次不是幅度问题，
  而是没蹬直，压根没离开蹬伸/腾空。
- **两个错误码是代理量，不是直接测量。** `SLJ_TAKEOFF_ASYNC` 与
  `SLJ_LAND_ASYNC` 判的是**膝角对称度**：单目视频没有足底接触信息，也无从确认
  真正的离地/触地时刻，两膝不对称是这件事最可见的痕迹。而且它抓得到的只有
  **中等幅度**的不同步 —— 两腿差得越大，膝角均值越够不到腾空线，那一跳会
  **不被计数**而不是被判为不同步。UI 措辞不得写成「测到了两只脚落地的时间差」。
- **`SLJ_LAND_STIFF` 判的是落地段膝角的极小值**，不是越界帧计数 ——
  用帧计数会把落地前后的过渡帧全算进去，每一次落地都被误判。
- **人在画面里会移动，站位提示因此不同。** 深蹲那句「让整个人进到画面中间」
  写在原地动作上是对的，搬到立定跳远上正好是反的：站在正中等于把跳出去的那一米
  主动让出画面，落地的几帧全在画面外。所以清单第一行显示的是
  `ActionSpec.framingHint`（「别站在画面正中：往前跳的那一米也要留在画面里」），
  同一句还会在开跳前说一次、并在一次都没数上时留在计数屏上。
- **出画之后要重同步。** 人跳出画面那几帧里状态机停在哪儿是随机的，而多半停在
  `LAUNCH`（出画瞬间恰好是蹬伸最快的时候，而「蹬直」这条线只差 4°）。不处理的话
  回来那一下蹲会被读成**回蹲**，一次真跳连同一次本来看得见的落地一起变成一次丢弃。
  处理它的是 `ActionDefinition.lossRecovery`，**落地仍然要靠看得见的蹲下来认定**
  （见设计文档 §4.3）。**它拦不住的一种情况**：落地整个人都在画面外 ——
  从头到尾没有任何一帧看到落地，那一次不会被计数，只会如实记成一次丢弃。
- **测不出距离。** 单目无世界坐标（设计文档附录 A），所以首页卡片上那句
  「只判动作规范性，测不出厘米成绩」在上线之后照留。

## 开合跳

同一页、同一条流程，而**机位正好反过来：它要正对镜头**。

- **机位只能是正面，不是「选得好」。** 判「落地膝内扣」的
  `frontal_knee_angle_max` 与判「开得够不够」的 `leg_spread_ratio` 都声明
  `views: [frontal]`，45° 下它们是 `view_mismatch`，**两条判定静默消失**。
  所以门禁的极性也跟着反了：`ActionSpec.requiresFrontal` 为真时，
  **不是正视就拦**（45° 与侧视一起拦）。用「不是正视即拦」而不是「等于侧视才拦」
  是有意的 —— 45° 下那两个量同样是机位不匹配，那是同一种失效，只是轻一点；
  只拦侧视的话，用户会停在 45° 上做出一整组量不出分腿幅度的动作，
  而屏幕上只写着一句「请正对镜头」，他会以为自己已经站对了。
- **站对了就不说话。** 开合跳没有「提示级」的站位偏差（`advisoryAdvice` 为
  `null`）：要么正对着、要么拦住，中间没有第三种结论。
- **代价落在标定上，这是本轮唯一一处「不改共享组件就做不成」。** 正面机位下
  `heel_rise_ratio_L`（声明 `[sagittal, oblique45]`）恒不可用，而
  `Calibrator.feed` 原先硬性要求它 —— 标定条会卡在 0、**不报任何错**、
  永远进不了计数。所以标定要求的基线量变成了**随动作而变**：
  `ActionSpec.calibrationBaselines`，开合跳那一组是「膝角 / 躯干倾角 / 分腿比」，
  深蹲与立定跳远不传、走的仍是原来那三个。**这台标定器在四个时机分别建出来**
  （字段初始化、开始标定、复位、标定期丢帧重来），所以
  `squat_session.dart` 里把它收成了一个工厂方法 `_newCalibrator()` ——
  手改四处的话，漏掉「标定期丢帧重来」那一处的表现与主线那次一模一样，
  而它几个月都未必被触发一次。
- **必需关键点也跟着换了。** 开合跳不要把左脚跟/左脚尖留在名单里
  （`jjRequiredLandmarks`）：留下来的话，正对镜头做开合跳的人左脚一出画就会被拦住，
  而拦他的理由说的是「脚跟离地判定做不了」—— 一件这个动作根本不做的事。
- **只有四条分段线是相对本人基线的，三条判定全是绝对阈值。** 分腿比已用肩宽
  归一、肩角与额状面膝角都是夹角 —— 这几个量本来就不需要个体化。
  **尤其不能给分腿幅度挂基线偏移**：并腿站立时分腿比接近 0，「基线 × k」也接近 0，
  而判据是「峰值 < 阈值」，阈值恒接近 0 而峰值恒大于 0 —— 那条规则会**永远不触发**
  且不报错（`jj_test.dart` 与 `test_jj.py` 两侧各有一条把这件事变成可执行的）。
- **只开到一半的跳不算一次。** 计数门槛是 `OPEN`（`bottomState`），
  没开到位的那些走 `discardedReps`，界面上说「有 N 次没计入（腿没张开到位，或中途人出画）」。
  取 `OPEN` 而不是 `OPENING` 的理由是：取后者的话，一次几乎没动腿的抖动也会被计成一次，
  而规则只会说「分腿幅度不足」—— 用户被告知了一个他并没有做的动作有问题。
- **相位词不同**：并腿站立 / 起跳 / 分腿展臂 / 落地合拢（`jjHudStateLabels`），
  与预览页那四拍逐字一致、顺序一致（`exercise_preview_test.dart` 里遍历
  `kActionSpecs` 比这件事）。
- **正视预览画不出屈膝，所以它忽略 `knee`。** 正面站着的人屈膝是往画面里弯的，
  二维画不出来；早先照搬侧视的画法，`spread: 26, knee: 20` 时两条小腿各自往外撇，
  是一双罗圈腿。`preview_poses.dart` 里 JJ 四拍一个 `knee` 都不填，
  `exercise_preview.dart` 的正视分支也不再应用它 —— 两条合起来才是完整的修法。
- **它测不出什么（卡片 `note` 上就是这么写的）**：落地缓冲要的是膝盖屈伸，
  而正面画面上屈膝几乎不改变投影角度；前后漂移的方向在正面就是镜头方向本身。
  这两个量在这个机位下不成立，硬做出来的规则只会是一条永远不触发、或者随机触发的规则
  —— 那比没有更糟，因为它假装在检查。所以 `JJ_LAND_STIFF` 与 `JJ_DRIFT`
  继续留在 `server/app/taxonomy.py` 里不实现。
- **落地膝内扣只作提示，而且它是这条判定第一次真正跑起来。** 阈值取 8°，
  依据是设计文档 §5.2 的最小可检测差异；措辞不得写成「测到了膝内扣多少度」。
  注意方向：`frontal_knee_angle_*` 是**直腿 0°、越扣越大**，与 `knee_angle_*`
  （直腿 180°）正好相反。顺带一句值得记住的事：深蹲有一条同名规则用的就是这个特征，
  而深蹲跑 45° —— **那条在产品里一帧都没执行过**，下一个人多半以为它在工作。

## 俯卧撑

同一页、同一条流程，**机位回到 45° 主链路**（深蹲与立定跳远的那个）。
它不需要开合跳那三处共享组件改动，代价换成了另一种 ——
门禁还有一处默认值是按「站着的人」写的：

- **「离得远不远」量的是纵向跨度，而趴着的人纵向只剩身体的厚度。**
  不处理的话，一个距离站得完全正确的人在整组里都会看到一条**拦人级**的
  「离得有点远（身高只占画面 10%）」—— 那句话说的不是事实，而且它拦人。
  现在的做法是**一律**取纵向与横向里**较大的那个**跨度，不再按姿势分叉。
  取较大者而不是「趴着就用横向」：自检与标定那一段人是站着的，取 max 会自动落回
  身高，门禁不必知道用户现在是什么姿势 —— 对直立的人 max 取到的就是纵向，
  所以三个既有动作**零行为变化**（`camera_position_check_test.dart` 里有一组守卫
  钉住这件事）。**这句话里那个词也跟着胜出的那一维走**：横躺着的人占到的是「身体」
  而不是「身高」，一律说「身高」会把人引去按站着的方向找一个不存在的问题。
  分叉的原型是一个 `ActionSpec.isLyingDown` 字段，**它已经删掉了**：横屏之后
  「转正图」变成宽大于高，站着的人若只按高度占比会被判成「离得远」、
  横躺着的人若只按高度占比则反过来偏小 —— 两种误报都指向一个并不存在的距离问题，
  而门禁这一层本来就拿不到「用户现在是什么姿势」，任何按姿势分出来的支路都只能是
  调用方传进来的一个常量，常量错了没有任何东西会报。
  **这两个阈值对趴着的姿势是未标定的**，与 `frontalRatio` 同一种状态。
- **标定对它是走过场，但那 15 帧躲不掉。** 会话的状态机要求标定走完才建定义，
  而俯卧撑四条判定**一条基线都不用**（肘角是关节夹角、体线偏移已用躯干长归一）。
  所以 `calibrationBaselines` 收到框架强制要求的那两项（膝角、躯干倾角），
  不去顺手多采一个**没有任何人读**的脚跟抬升 —— 多采一个的代价见下一条。
- **必需关键点里没有脚跟与脚尖，但**有四**个容易漏的点：双肘与**双腕**。**
  肘角既是分段信号又是两条规则的输入；手腕看不见时它就消失了，
  状态机永远不离开「支撑」——**一次都数不上，而屏幕上什么错都不报**
  （`puRequiredLandmarks` 是把这件事说清楚的地方，不是把那份名单手写一遍）。
- **「算不算一次」与「做得好不好」是两条线。** 下不到 `pushupDepthDeg`（100°）
  的那些不进计数、走 `discardedReps`；`PU_INSUFFICIENT_DEPTH` 判的是进来的那些里
  肘角峰值高于 90° 的。顶部同理：`pushupTopDeg`（165°）是分段线，
  `PU_INCOMPLETE_EXTENSION` 判的是 165°–170° 那一段。两条线都是可调的工程参数，
  顺序写反会当场抛（`buildPushUp` 的构造期断言）。
- **塌腰与撅臀共用 `body_line_offset_ratio`，方向相反。** 现成的 `body_line_angle`
  是个 0–180° 的夹角，髋往上顶和往下掉都只是让它变小，**两种错在它上面逐位相同**
  （`pu_test.dart` 与 `test_pu.py` 里各有一条断言量了这件事）—— 所以这一轮新造了
  一个带符号的量，正 = 髋更低 = 塌腰。符号取的是重力方向而不是「连线的哪一侧」：
  后者会随人面朝画面哪一边翻号，同一个塌腰在两个站位上会得到一正一负。
  写反任何一条规则的表现只是「这两条判定怎么老是乱报」。
- **四条判定都跑在整段上（`Phase.ALL`），而且显式写着。** 它们问的都是
  「整次动作的极值」，而「支撑」这个状态本来也不该映射相位。写一个没被映射的
  相位靠 `RepWindow.select` 的整段回退兜住，行为一模一样、测试也不会红 ——
  所以钉的是**意图**不是行为（`test_pu.py` 里那条）。
- **相位词不同**：支撑 / 下放 / 最低点 / 撑起（`puHudStateLabels`），
  与预览页那四拍逐字一致、顺序一致。
- **它测不出什么（卡片 `note` 上就是这么写的）**：肘外展要的是上臂相对躯干在
  **额状面**内张开的角度，而侧视/45° 画面上「手臂往前摆」与「往两侧张」
  投影同形 —— 这个量在这个机位下不成立，所以卡片上原来那半句承诺收掉了。
  头颈位置要一个还不存在的特征。两者都继续留在 `server/app/taxonomy.py` 里不实现。

## 仰卧起坐

同一页、同一条流程，**机位回到 45° 主链路**（与深蹲、立定跳远、俯卧撑同向：
要侧身）。它的骨架与深蹲同形 —— 一个中立位、一个最低点、两侧各一段行程 ——
连相位映射都逐字复用。代价是三条必须写在注释里的东西，它们在屏幕上都不报错。

- **「坐起线」取不到 1.0，这不是调参口味，是一个物理上界。**
  `shoulder_height_ratio` 量的是**肩比踝高多少**；臀贴在垫上时肩绕髋转，
  于是 `比值 = cos(躯干与竖直的夹角)` —— **上界恰好是 1**，而 1 只在
  「躯干严格竖直」那一个奇点上取到。国标的收势是前倾（肘触膝），前倾 30° 就只有
  0.87：**取 1.0 会让标准动作永远不被计数，而且什么错都不报**。
  更坏的是它会奖励正要被罚的那个错 —— 臀一离垫，肩被顶高，比值能越过 1.0，
  老老实实做的人够不着线、顶着髋借力的人够得着。所以 `situpSeatRatio` 取 0.75
  （躯干距竖直约 41° 以内）。这个数是**工程参数**（判的是「算不算一次」），
  同深蹲的 `minBend` 那样留在 `TrackingConfig` 里，不进阈值表。
- **三条判定各看一件事，而且三条都是绝对阈值**（`thresholdOffsets` 是空的）：
  肩胛贴垫看 `shoulder_height_ratio` 在**最低点**的最小值、
  顶髋借力看带符号的 `body_line_offset_ratio` 在**整段**上的最小值、
  屈膝角度看 `knee_angle_L` 在整段上的最大值。三个量要么已用躯干长归一、
  要么本来就是夹角 —— 体型在它们里面约掉了，再乘一个本人基线只会引入噪声。
- **顶髋那条必须跑在整段上（`Phase.all`），不能只盯最低点。**
  坐起的途中髋自然高于肩-踝连线（合成帧上量到 > 0.10），把窗口切到最低点就会
  把那一段当成顶点 —— 而这条规则的名字是「臀离垫借力」，报出来的是另一件事。
  `su_test.dart` 与 `test_su.py` 里各有一条断言钉住这件事。
- **起始姿势必须是躺着的，这是 `framingHint` 里那句话的全部意思。**
  门禁判「离得远不远」的两个数是按**站姿**标定的
  （`camera_position_check.dart` 自己写了「这两个数是按直立的人标定的」），
  而仰卧起坐的起始姿势偏偏是这一组里**最显小的那个**：同一个人、同一部手机，
  合成帧上躺下占画幅 45.1%、坐着只剩 26.2%，门槛是 45% 且**拦人级**。
  相机页的自动倒计时以「门禁放行」为条件（`squat_page.dart` 的 `_updateAutoStart`），
  过不去就永远不进标定 —— 用户看到的是「离得有点远，请靠近一些」，照做之后
  一躺下又变成「身体贴到画面边上」。**现在的办法是绕开它：让用户躺着开始。**
  要给坐姿定一个真数，得先有真机数据；`su_session_test.dart` 里那条
  「坐姿会被距离判据拦下」是**记账断言**，它钉的是「坐姿过不去、躺姿过得去」
  这个事实本身（判据改成取 max 那次它**照样绿** —— 坐着的身体高仍大于宽，
  `max` 取到的还是高，所以别再指望它当上述判据的哨兵）。
- **计数点是「回到坐起」，不是「回到躺平」（与设计文档 §4.3 的一处出入）。**
  §4.3 写的是「回到 `LYING` 且肩胛触垫确认」，而引擎的 rep 缓冲从**离开**
  restingState 那一帧开始、到重新进入它时封存 —— 把 `LYING` 当 restingState，
  「这次肩到底贴到垫上没有」那个证据正好落在缓冲的边界上，而且**偏向起得快的人**
  （防抖让封存晚几帧，起得越快封存时肩已经多降了一截，读数越小）。
  换成 `restingState = SEATED`、`bottomState = LYING` 之后，躺平那一段落进缓冲中段，
  `Phase.bottom` 上的最小值才恢复它本来的意思。代价是启动时状态机停在 `SEATED`，
  HUD 上「坐起」那个词会闪一下，等用户躺下就翻过去。
- **标定对它是走过场，但那 15 帧躲不掉**（同俯卧撑）：三条判定一条基线都不用，
  所以 `calibrationBaselines` 收到框架强制要求的那两项（膝角、躯干倾角）。
- **必需关键点正好是躯干四点加双腿六点**（`suRequiredLandmarks`），
  一个不多一个不少：不要把左脚跟/左脚尖留在名单里 —— 留下来的话，躺下去之后
  左脚一出画就被拦住，而拦他的理由说的是「脚跟离地判定做不了」，
  一件这个动作根本不做的事。
- **相位词不同**：仰卧 / 起身 / 坐起 / 躺回（`suHudStateLabels`），
  与预览页那四拍逐字一致、顺序一致。第三拍那个词是**「坐起」不是「触膝」**：
  状态机只知道「肩高过了坐起线」，并不知道手肘碰没碰膝盖 ——
  「触膝」比规则能做到的多说了一件事。
- **它测不出什么（卡片 `note` 上就是这么写的）**：「双手有没有抱住头」与
  「手肘有没有触到膝盖」都是**接触关系**，而 2D 关键点之间的距离在透视下分不出
  「贴着」与「一臂之遥」—— 这两个量在单目下不成立，硬做出来的规则只会永远不触发、
  或者随机触发。所以 `SU_HANDS_OFF_HEAD` 与 `SU_ELBOW_NOT_TOUCH_KNEE`
  继续留在 `server/app/taxonomy.py` 里不实现。

## 跳绳

同一页、同一条流程，**机位回到 45° 主链路**（与深蹲、立定跳远、俯卧撑、仰卧起坐
同向：要侧身）。共享组件一处都不用动，但它有两条别处都没有的前提，
而两条**在出问题的时候都不报错**。

- **机位必须是 45°，理由与立定跳远一模一样。** 判「离没离地」的 `foot_height_ratio`
  与判「单脚落地」的 `foot_gap_ratio` 都声明 `views: [sagittal, oblique45]` ——
  正视机位下它们是 `view_mismatch`，**分段信号整段不可用**，机器于是永远停在
  `GROUND`：一次都数不上，而 HUD 上一直安安静静地显示着「双脚着地」。
  拦住这件事的还是首页那道站位门禁（`rope_session_test.dart` 里有一条
  「45° 放行、正视拦住」的断言）。
- **手机必须架稳不动 —— 这是这个动作独有的前提。** `foot_height_ratio` 是
  **全仓库唯一一个拿画面当零点的量**（别的动作都刻意避开，因为画面上下的位移
  一半来自人自己的移动），它能这么做只因为跳绳有一条别人没有的条件：手机立住不动，
  于是画面下缘在一整组里是一个固定不动的水平面。**手机一动，这条线跟着动，
  而屏幕上什么都不会说。** 所以它写在 `ActionSpec.framingHint` 里：
  「把手机架稳别动」。**这就是那条提示与别的动作不一样的全部原因** ——
  不是语气，是判据本身的要求。
- **标定姿势对它也有额外要求：站稳在地上。** 三条分段线全部记成相对本人站立基线的
  增量（`footHeight` 的绝对值由机位高低决定 —— 手机架在腰高还是胸口高，
  同一个站姿的读数能差一大截），代价是**这是唯一一个「基线本身就代表接触地面」的
  动作**：标定时踮着脚，整组都会跟着偏移。
- **第三个状态 `CUSHION` 不是装饰。** `GROUND ⇄ AIR` 两态**看起来**够用，
  但 rep 缓冲是「离开 restingState 那一帧开始、重新进入它的那一帧封存」——
  两态下**封存发生在脚尖刚碰到地面的那一帧**，而落地缓冲（膝屈再伸的那一下）
  全部发生在之后：`ROPE_LOW_BUFFER` 要判的那段证据整个落在 rep 窗口之外，
  规则照常产出结论、说的却是另一件事。所以触地只进 `CUSHION`，封存要等到
  「脚尖贴回地面 **且** 膝角回到站立线」。**这不是为跳绳特设的机制**：
  `pu.dart` 的 `TOP`、`situp.dart` 的 `SEATED` 都在解决同一件事 ——
  把「这次做没做到位」的证据塞进窗口里，而不是压在边界上。
- **没跳起来的那次不算一次**（计数门槛是 `AIR`，`bottomState`）。取 `CUSHION`
  的话，一次原地提踵就会被计成一次跳绳，而规则只会在别的地方挑毛病。
- **防抖那一组数（`voteWindow` / `voteRequired` / `minDwellFrames` = 2 / 2 / 1）
  是被节奏逼出来的，不是口味。** 状态机每次转移都会清空投票历史，所以每个状态都要
  在状态内重新凑满票，三态环最短 3 × 2 = 6 帧；默认那一组（5/4 + 3）是每状态 5 帧、
  一轮 15 帧 —— 20 fps 下 0.75 秒一次，**会把跳绳数成一半**，而界面上一切正常。
  取最小值的代价也要写清楚：一轮只有 2 帧防抖，滤不掉连续两帧的关键点抖动。
  真机上如果发现**多计**，第一个该调的是 `voteWindow`（调到 3），
  **不要**去调那三条分段线 —— 那是判「离没离地」的，与多计无关。
- **三条判定**：`ROPE_LOW_BUFFER`（`knee_angle_L` 整段最小值）、
  `ROPE_TRUNK_LEAN`（`trunk_lean` 整段最大绝对值，**相对本人站立基线**）、
  `ROPE_SINGLE_LEG`（`foot_gap_ratio` 整段最大值，**绝对阈值**）。三条都取极值
  再比线，不是逐帧计数 —— 一次跳绳十来帧，帧计数会把过渡帧全算进去，每次都误判
  （同深蹲为深度规则写下的那条理由）。
- **相位映射是空的**（`stateToPhase` 为空表），三条规则全部跑在 `Phase.all` 上。
  不映射 `CUSHION` 是有意的：落地缓冲只有 2–5 帧，拿它当相位窗口会让「膝屈得最深
  的那一帧」有大概率落在窗口外，而 `RepWindow.select` 对没有区间的相位
  **退化为整段** —— 那是一条静默的误判路径，量出来的东西与相位名无关。
- **它测不出什么（卡片 `note` 上就是这么写的）**：计数是估算，
  **它看得见人、看不见绳子**；交替跳与前后位置漂移也都测不出来 ——
  前者是「组内这几跳是不是左右换着落脚」，一个跨次的时间序列模式，
  而规则引擎对每一次动作独立求值；后者的「前后」在 45° 机位里几乎就是镜头方向
  本身，单目无世界坐标时量不出来。三个都继续留在 `server/app/taxonomy.py`
  里不实现 —— 那张表的文件头写了为什么这是刻意的。
- **相位词不同**：双脚着地 / 腾空 / 落地缓冲（`ropeHudStateLabels`），
  与预览页那三拍逐字一致、顺序一致（预览从四拍收到三拍，就是让两边对上）。

## 引体向上

同一页、同一条流程，**机位回到 45° 主链路**。共享组件一处都不用动，但这一节有
几条别处没有的东西，其中三条**在出问题的时候都不报错**。

- **机位回到 45° —— 但理由与深蹲、立定跳远**不是**同一条，要说清楚。**
  它三条判定的特征（`elbow_angle_*` / `mouth_wrist_dy` / `trunk_lean`）都
  **没有机位门控**，正对镜头时照样算得出数 —— 所以它不像跳绳那样「正视直接卡死」。
  代价藏在另一处：`trunk_lean` 量的是躯干**在画面上**偏离竖直多少，而摆动借力是
  身体在**前后**荡。正对镜头时那个方向就是镜头方向本身，特征照样有值、
  只是不再表示荡没荡 —— `PULLUP_SWING` 于是**静默地变成一条永不触发的规则**。
  这一条是**语义**消失，不是数值消失，比前几类更难看出来。
  `pullup_session_test.dart` 里有一条「45° 放行、正视拦住」的断言。
- **计数门槛用肘角，不用下颌过杠 —— 这是刻意选的。** 国标认的是下颌过杠，
  而本项目也量得到它，但它**不参与计数**：嘴是 33 个点里可见性最低的几个之一，
  拿它当计数门槛的后果是「拉到位了但脸被挡住 → 这一次不算」。肘角是
  肩-肘-腕三点，在同一个动作里稳定得多。口径是那句
  **「少判一次是提示，少计一次是丢数据」**。
- **`mouth_wrist_dy` 不是代理量，是一条几何恒等式。** 双手握在杠上，
  所以腕的高度**就是**杠的高度，`嘴_y − 腕_y < 0` 与「下颌过杠」是同一件事。
  分母取躯干长，于是身高与镜头远近在里面约掉。**带符号，所以那条阈值是个负数**
  （`pullup.chin_over_dy_max`，随包值 −0.05）—— 谁把它改成「取绝对值再判」，
  都会把「挂在杠下」和「拉过头」压成同一个数，而这条规则只有一句纠正建议。
- **下颌过杠那条切在顶点段（`Phase.apex`），而且它的遮挡容错只是部分的。**
  切窗口的理由是「读不到就不判」：跑在整段上时，嘴只要在**组里任何一帧**看得见
  （比如悬垂时），`reduce: min` 就会取到那个悬垂读数，于是脸被上臂挡住、
  其实拉得很到位的人会被判成「没拉上去」。**但那个窗口的尾巴上有几帧其实属于下放段**
  ——状态机换相要经过驻留与投票，确认滞后于特征值的变化。所以只有当嘴从顶点段起
  一路遮到下放段也读不到时，这条规则才真的退回「不知道」。准确的说法是
  **「永不比整段宽松，且在部分遮挡下更严格（严格的方向是少报）」**，
  而不是「挡到脸就一定不报」。两个动作测试里为此各有一对断言：
  遮挡后不触发，以及**同一批帧把窗口换回整段就必须触发** —— 后半条是决定性对照。
  `Phase.apex` 的文档里同时记了这条泄漏对每一个相位成员都成立。
- **四个状态、两条回退边**：`HANG → PULLING → TOP → LOWERING → HANG`，
  `PULLING → HANG`（假动作）与 `LOWERING → PULLING`（下放到一半又拉上去）
  各自让这两种情况能自己走回来。计数确认点就是**回到直臂悬垂**，
  所以「没拉到位就落回来」的那些走 `discardedReps`，界面上说的是
  「有 N 次没计入（没拉到顶，或中途人出画）」—— 用户看到的是「这次没算」，
  而不是「这次算了一次但姿势不好」。
- **标定是在杠上做的 —— 这是唯一一个这样的动作。** `pullupSpec` 的基线集只有
  框架强制要求的两项（`BaselineKey.alwaysRequired`：膝角、躯干倾角），
  三条判定一条基线都不用。默认那三项里多出来的 `heel_rise_ratio` 在这里
  **按定义就是错的**：标定时这个人是挂在杠上的，采出来的「站立基线」不是站立姿势下
  的数。一个没人读、含义还是错的量，比少采一个更糟。代价是用户要在杠上稳住
  15 帧（约 1 秒）—— 直臂悬垂本来就是稳的，这也是它能这么做的原因。
- **必需点名单里最不能漏的是双腕。** 手看不见时 `elbow_angle_*` 算不出来，
  状态机永远停在 `HANG`：**一次都数不上，而屏幕上什么错都不报**
  （HUD 一直显示「直臂悬垂」，那正好是实情的一半）。而门禁的缺失判据只有
  「躯干 / 腿 / 左脚」三组，**手腕不在里面，所以它拦不住这件事** ——
  这是一条记下来的边界（`pullup_session_test.dart` 里有一条断言把它钉住，
  不是默认它不存在），产品上靠 `framingHint` 那一句话与
  `PoseQualityTracker` 的覆盖率（它用的是同一份名单）兜着。
  名单里**没有脚跟与脚尖**：这个动作一条判定都不碰它们，带上它们的后果是
  挂在杠上的人左脚一出画就被拦住，拦他的理由说的是「脚跟离地判定做不了」。
- **站位提示也是别处没有的一句**：「把手机架到能同时看见横杆和双脚 ——
  手看不见就一次都数不上，脚看不见标定过不去。」前后两句分别对应上面两条，
  没有一句是客套话。
- **三条判定**：`PULLUP_NOT_DEAD_HANG`（`elbow_angle_L` 整段最大值低于线，
  即全程没伸直过手）、`PULLUP_CHIN_NOT_OVER`（顶点段 `mouth_wrist_dy`
  最小值）、`PULLUP_SWING`（`trunk_lean` 整段最大绝对值）。三条都取极值再比线，
  不是逐帧计数。三条都用**绝对**阈值，一个本人基线都不挂 —— 肘角与倾角是关节角/
  绝对角，嘴高差已经用躯干长归一过。
- **`PULLUP_NOT_DEAD_HANG` 的线必须高于分段线。** 封存一次引体向上的前提恰恰是
  「肘角回到 `pullupHangDeg` 之上」，所以每一个被计数的 rep 其整段最大值都必然
  高于它。阈值若定在它之下，「最大值越界」恒假 —— 这条规则**永远不触发、
  也不报错**，看起来就像「没有人犯这个错」。测试里有一条专钉这件事。
- **相位词不同**：直臂悬垂 / 上拉 / 顶部 / 下放（`pullupHudStateLabels`），
  与预览页那四拍逐字一致、顺序一致。
- **它测不出什么（卡片 `note` 上就是这么写的）**：组内悬垂休息超时
  （`PULLUP_REST_TIMEOUT`）判的是**跨次**的时间间隔，而规则引擎对每一次动作
  独立求值；腿的摆动与屈膝在 45° 机位下与躯干的前后摆同形。两个都继续留在
  `server/app/taxonomy.py` 里不实现 —— 那张表的文件头写了为什么这是刻意的。

## 平板支撑

同一页、同一条流程，**机位回到 45° 主链路**（要侧身）。这一节里有一件别处没有的
东西 —— **它是全仓库第一个「计时制」的动作**：它的 rep 是**一段时间**，不是
「一次动作」。领域层为此一行都不用改，改的是**界面把这个时间显示出来**。

- **一次 rep = 一段连续支撑。** 状态机在「离开 `HOLD_BREAK`」那一帧开窗、
  在「回到它」那一帧封存，所以 rep 窗口就是那一段支撑本身。于是这个动作的两个
  产出正好是卡片承诺的那两件事：**每段撑了多久**（rep 窗口首末帧时间戳之差，
  早已进决策契约的 `duration_ms`）与**每段犯了什么错**。
- **计数屏的大字换成了正在走的计时器**（`CountingHud` 的 `isTimed` 分支），
  计数退到下面一行、单位改叫「段」。一段 40 秒的支撑被显示成「1」，用户会以为
  计数器没在看他 —— 这个动作里「唯一会动的数」就是撑了多久。
- **膝角条整个撤掉，而不是换成别的条。** 平板支撑里膝角恒在 180° 上下（站着
  是这样、撑着也是这样），一条不动的条不是「相机在量我」的证据，而是一条**假的**
  证据。这一屏上真正的证据是那个在走的计时器 —— 它每一帧都跟着相机的时间戳走。
- **计时器只在 `isTimed` 时才算**（`SquatSession._holdElapsedMs`，读
  `ActionRunner.openRepStartMs`）：别的动作的屏幕上没有任何地方会显示「这一次
  撑了 0.8 秒」，为一个不显示的数每帧算一次是白算。
- **时长公式只有一份**：`RepWindow.durationMs`。报告里那一行、语音里那一句、
  以及决策请求里的 `duration_ms` 都从它来（两个适配器都改成委托）——
  三处各写一遍的话，屏幕上的秒数会与请求里的数悄悄分叉。
- **报告与语音说「段」、不说「个/次」，并把每段时长摆上来。** 报告里那一行是
  `合计 92.5 秒（每段 41.0 / 30.2 / 21.3 秒）`；语音念「本组结束，一共三段，
  合计九十二秒」（**取整秒**，报数这条通道不念小数点）。非计时制动作一个字都不变。
- **分段门是三件事的合取**：身体放平 + 体线大致成一条线 + 前臂在支撑带上。
  一条都不能省 —— **站着的体线也直**（只看体线，标定那 15 帧站立会被读成一次
  长支撑），**趴着放松也直也水平**（只看前两条，中途趴下休息算「撑着」）。
- **门槛比判据宽。** 塌腰 0.20 判错、塌到 0.45 才算「离开支撑位」—— 中间那一段
  正是规则有活干的地方（同开合跳的分腿幅度、俯卧撑的深度）。
- **规则门槛 8 帧，比别的动作大得多（它们取 2）。** 两个原因：计时制的窗口动辄
  几百帧，抖一下不该在四十秒里变成一次犯规；而窗口的尾巴上有几帧**不属于支撑段**
  —— 状态机换相要经过驻留与投票，「离开支撑位」被确认时那几帧人其实已经塌了，
  取 2 会让**每一次正常收势都被判成塌腰**。
- **两条肘角阈值必须严格落在支撑带里面**（随包 110°/70°，带是 130°–50°），
  否则每一个被计数的 rep 都够不着那条线，`PLANK_ELBOW` **永远攒不够 8 帧、
  一次都不触发、也不报错**。同引体向上与开合跳那两条陷阱。下沿那条余量最小。
- **一个错误码两条规则**：`PLANK_ELBOW` 由「撑得太直」与「撑得太塌」共用，
  引擎按错误码去重，所以组级不会翻倍。**不要拆成两个码。**
- **撑完一段、站着歇够 10 秒，本组自动收工**（`autoFinishRestMs`）。
  这个动作没有「一次动作的终点」可以等 —— 歇够了就是练完了。
- **它测不出什么（卡片 `note` 上就是这么写的）**：一个**趴在地上**的人摆出同样的
  关节构型（前臂撑在身侧、肘角 90°、身体成一条线），在单目投影下与真正的平板支撑
  **完全同形** —— 两者的差别只有「离地多高」，而单目无深度参照。这是**能力边界，
  不是没排期**。缓解只有两条、都不是判定：门禁要求全身入画，以及屏幕上那个状态词
  （用户看得见系统把它读成了什么）。头颈位置（`PLANK_HEAD`）也不判，因为它要一个
  还不存在的特征（耳/眼相对躯干长轴的偏角）。
- **相位词只有两个**：撑住 / 没在撑（`plankHudStateLabels`），与预览页那两拍
  逐字一致、顺序一致。「没在撑」是**中性描述现状**（系统现在没看见你在撑），
  不是指控 —— 一组里第一段之前人也在这个状态，那时他一次都还没撑过。

## 坐位体前屈

同一页、同一条流程，**机位回到 45° 主链路**（要侧身），并且**进练习页先锁横屏**
（坐到垫上之后整个人是横着铺开的，见「[横屏与方向](#横屏与方向)」）。它的状态环
与仰卧起坐同形（一个中立位、一个最低点、两侧各一段行程），但**分段的那个量是反着的**，
这一条是本节最容易照抄错的地方。

- **`hip_angle_L` 是「越小越前折」，与仰卧起坐正好相反。** 那边量的是
  `shoulder_height_ratio`（肩比踝高多少，**越大越躺平**），这边量的是
  肩—髋—膝的夹角：坐直 ≈ 90°、前伸到底 ≈ 30–50°。所以三条分段线
  （`sitReachUprightDeg` 75° / `sitReachHoldingDeg` 55° / `sitReachHysteresisDeg` 8°）
  的比较方向与 `situp.dart` 那一份**逐条反向**。照抄仰卧起坐的写法不会报错 ——
  状态机照样「跑得动」，只是计数变成了「折得越浅越算一次」。
  这三个数是**工程默认值**（判的是「算不算一次」），留在 `TrackingConfig` 里，
  不进阈值表。
- **计数点是「坐直」，不是「前伸到底」（与仰卧起坐同一条理由）。** 引擎的 rep
  缓冲从**离开** restingState 那一帧开始、到重新进入它时封存，所以
  `restingState` 取 `SIT_UPRIGHT`、`bottomState` 取 `HOLDING`：
  「这一次有没有真的前伸到底」这个证据落在缓冲中段，而不是压在边界上。
  伸到一半又坐直的那些走 `discardedReps`（卡片上那句话是「没伸到底」）——
  **「算不算一次」与「做得好不好」是两条线**：屈膝、弹振的那些次**照样算一次**。
- **起势那一段不能省：`SIT_UPRIGHT → HOLDING` 不是一条边。** 状态机要先在
  `REACHING` 里攒够证据才换相，合成帧里少写前伸那一段的话，「保持」那一段会先在
  `REACHING` 里被投票 —— 行为与真实动作对不上（`synthetic_srt.dart` 里写了这件事）。
- **两条判定的窗口不一样，而且必须不一样。**
  `SRT_KNEE_BENT` 取**前伸到底那一段**（`Phase.bottom`）：前伸途中膝盖松一下
  没人管得着，屈膝只有在前伸到底那一刻才说明问题（膝盖一弯，上身就够得更远）。
  `SRT_BALLISTIC` 取**整段**（`Phase.all`）：弹振发生在**前伸的过程中**，
  靠来回弹把人甩出去的，前伸到底之后可以完全是静的。
  窗口写反的表现是同一件事 —— 这条判定时不时冒出来，而看不出病因 ——
  所以两侧各有反例钉着（`sit_reach_test.dart` / `test_sit_reach.py` 里
  「前伸途中屈膝」与「平稳前伸」两条），并且直接量了封存窗口上两个相位各数出几次
  掉头（**底部 0 次、整段 5 次**）。
- **`SRT_BALLISTIC` 不能拿一条深度类规则顶替。** 靠弹振够距离的人，前伸到底那个
  角度可能与慢慢伸的人**一模一样、甚至更远** —— 拿 `min(hip_angle_L)` 之类的量去判，
  两种人分不开。所以这一轮给规则引擎加了**第五个归约** `Reduce.reversals`：
  窗口内相邻帧差分**符号翻转的次数**，带 `reversalDeadband`（2°）的死区。
  这是全仓第一次因为一个**错误的形态**（而不是一个**量的缺失**）去扩引擎。
  死区不能省：匀速前伸叠上读数抖动时，关掉死区会把同一段动作数成上百次掉头
  （`test_rules.py` 里那条断言把它量出来了）。
- **正对镜头是静默失败，而且是这一节唯一「特征层拦不住」的事。**
  `hip_angle_L` 与 `knee_angle_L` **都没有 `views` 门控** —— 正视下它们照样有数
  （与仰卧起坐那两个带门控的量正好相反，`sit_reach_test.dart` 里那条断言把它钉住了）。
  可正对镜头时前折发生在**镜头方向本身**上，画面里的髋角几乎不变：状态机永远停在
  `SIT_UPRIGHT`，一次都数不上，而 HUD 一直显示「坐直」—— 那正好是实情的一半。
  所以 45° 这件事只能靠 `blockingAdvice` 用话讲清楚，站位门禁那三层（机位/入镜/
  距离）里没有一层能替它把关。
- **标定对它是走过场，但那 15 帧躲不掉**（同俯卧撑与仰卧起坐）：两条判定一条基线
  都不用 —— 髋角与膝角都是关节夹角，体型在它们里面约掉了，所以
  `thresholdOffsets` 是空的。标定时人**已经坐在垫上**（`framingHint` 说的就是这件事，
  与俯卧撑「先站着标定再趴下去」相反）。
- **必需关键点正好是躯干四点加双腿六点**（`srtRequiredLandmarks`，与仰卧起坐同形），
  **不要脚跟脚尖** —— 留下来的话，坐下来之后脚一出画就被拦住，而拦他的理由说的是
  一件这个动作根本不做的事。
- **相位词**：坐直 / 前伸 / 保持 / 坐回（`sitReachHudStateLabels`），与预览页那四拍
  逐字一致、顺序一致。
- **它测不出什么（卡片 `note` 上就是这么写的）**：国标量的是**厘米**（指尖超过脚尖
  多少），端侧量不了 —— 单目没有世界坐标，量不出绝对长度（设计文档附录 A 那条老账）。
  **横屏也不是为了量长度**，是让整个身体进得了画面。「双手有没有并拢」这一轮也没做：
  它要新增一个特征算子，而按仓库的工程约定，加特征 = 两侧实现 + 重生成
  `shared/fixtures/feature_conformance.json` + 两侧测试全绿。这个码继续留在
  `server/app/taxonomy.py` 里 —— 理由写在那边。

### 一组做完之后

做完一组，`squat_page.dart` 按相位把 `appBar` 与 `body` **整个换掉**：报告占满全屏，
相机预览从树里摘掉，管线也**显式 `stop()`**。

停相机不是观感问题，是一处资源泄漏：`finishSet()` 只改相位，原先**没有任何人停相机**，
所以做完一组之后相机一直开着，直到页面被销毁。停的位置也不是「结束本组」那个按钮 ——
十秒无动作的**自动结束**发生在会话层的 `feed()` 里，按按钮根本不会被按到
（`_syncCameraForPhase` 挂在相位推送上看，两条路径都盖得住）。

**同一跃上还挂着记账。** `set_recorder.dart` 也在这一处产出这一组的记录，
理由与停相机逐字相同 —— 那一跃未必伴随新帧，也未必经过那个按钮，而它恰好是
「用户放下手机走开」的那一次。见「[历史记录](#历史记录)」。

**但它不是一次跳转。** 没有换路由、也没有换页面：`SquatPage` 那个 State 一直活着，
换的只是两段 widget。这一点是**有代价的做法的对立面** —— 推一条新路由就要重建
`SquatSession`（含标定）、决策客户端、三个目录缓存，以及 `AnalysisPanel` 的整个 State
（表单、已提交的请求、结果、地址）。「再来一组」会从「沿用标定」退化成「重新站位、
重新标定」。报告体本身在 `lib/ui/set_report_view.dart`。

**报告页的 AppBar 保留静音按钮**：语音播报的正是这一组的汇总，那一刻拿掉唯一的静音
手段是倒退。报告体外面必须是 `SingleChildScrollView` —— `AnalysisPanel` 自己不带滚动
（见它的类注释），而**漏掉外面那层不会编译报错**，只会在展开时表现为一条 overflow 条纹；
`set_report_view_test.dart` 里有一条测试专门盯这件事。

### 全程不用碰手机

45° 斜机位要求人离手机两米左右，**而按钮在手机上**。所以这条流程是设计成
不用碰它的：

- 四项自检一过 → **倒计时 3 个数自动开始标定**（按钮同时保留，人在旁边时更顺手）；
- 做完最后一个 → **站直 10 秒自动结束本组**。

中途人一离开画面，倒计时或标定就作废退回自检 —— 拦住比放行便宜：
放行一局算不出结果的动作，用户得到的是一屏没有意义的数字。

### 全程用听也行

**屏幕在两米外只是一块亮斑。** 所以同样的信息走一遍语音通道（`lib/app/voice_coach.dart`,
原生 `TextToSpeech`，没引新依赖），标题栏右边那个喇叭图标可以关掉它。默认是开的。

说的是这些：倒计时三个数 →「站直，别动」→「开始」→ 每数到一个报一次数 →
结束时「本组结束，一共十个，六次膝内扣倾向」。

**不做的事和做的事一样重要：**

- **不念界面上的字。** 界面那份是写给眼睛的（「请先按**上面那条**把整个上身放进来」
  ——听的人看不到「上面那条」；括号里的百分比念出来是噪音），所以另存一份口语短句。
  代价是多一处可能分叉的地方，用「每个错误码都必须有交代」的机械测试兜住。
- **不说提示级的问题。** 播报没法「扫一眼就跳过」，说了一条本来不用理的提示，
  就等于把它升级成了拦住。
- **不说单次 rep 的问题。** 做完一个就报一次「膝内扣倾向」，两个下来声音就成背景噪音了；
  而且那 74 条阈值全是 `pending_review`、措辞特意弱化过 —— 用提醒的口气说一个
  证据不足的判定比不说更糟。问题留到组末汇总一次讲清。
- **不说三位数以上的数**（一组深蹲数不到那儿，交给引擎念就行）。

**设备上可能根本没有能说中文的引擎** —— 演示机（小米）只有 `com.xiaomi.mibrain.speech`，
没有 Google TTS，`tts_default_synth` 是 null。所以引擎说不出话时应用会**弹一条
「语音引擎说不出中文，本局只能看屏幕」**，而不是安静地不响：用户会以为自己没听见，
一路做下去，到汇总才发现一个数都没有。另外清单里的 `<queries>` 元素是这条通道
能不能用的前提，Android 11+ 上缺了它 `TextToSpeech` 一构造就失败。

### 做完一组：组装决策请求

报告页里的「分析这一组」有张表单，把这一组组装成
`shared/contracts/decision_request.schema.json` 说的那个结构。**这份 JSON 一直看得到、
复制得了** —— 它当初是 Phase 1 的验收物，接了决策服务之后也没有丢掉，
在「原始数据」区里，成功与失败都一样在。详见下面的「[分析这一组](#分析这一组)」。

它要问四个问题（性别、年龄、年级、国标组别）—— 它们决定「和谁比」，猜不得：
给一个 16 岁女生按成年男子标准判，得到的结论比不给结论更糟。

**这四项现在会从「我的资料」预填进来，并标明出处与日期。** 这是对早先一条规则的
**显式推翻**（那一版写着「不持久化也不预填：一个上次留下的年龄看起来像是『已经
确认过』」）；「[我的资料](#我的资料)」那节里的五条对策就是**答那条意见**，不是绕开它。
两处年龄边界（资料页与这里的表单）共用 `decisionAgeMin` / `decisionAgeMax` ——
各写一份的话会存下一份面板自己拒收的档案。

**「不知道」在契约里有专门的写法，不许拿 0 顶替。** 组级的 `rom_mean_deg` 与
`symmetry_index_mean`、逐次的 `metrics` 与 `confidence` 全部留空 —— 领域层没有
这几个数，而一个填成 0 的活动幅度会被决策层读成「这组动作幅度为零」。
`pose_quality` 的五项则是**实算的**（`pose_quality_tracker.dart`），一帧一帧数出来的；
算不出来时**整个请求不给**，而不是拿 0 或估计值补上：决策层用这五个数决定
「这份数据够不够格下结论」，它没有任何办法分辨我们填的是测出来的还是拍的。

**两侧一致靠 fixture 锁，不靠人工对照。**
`shared/fixtures/decision_request_conformance.json` 由 Python 侧
（`server/app/adapter.py`，参考实现）生成期望请求，Dart 侧用同一批原始姿态跑一遍
完整链路再逐字段比对。漂移一定会在 `check_all.py` 的「请求 fixture 同步」或
`test/app/decision_request_conformance_test.dart` 里红掉。

**发出去的是这份 JSON，不是视频。** 现在它会被 POST 给决策服务（见下节），
但两端之间的全部内容就是这些结构化特征 —— 视频与关键点一帧都不出设备，
详见「[隐私边界：只传特征，不传视频](#隐私边界只传特征不传视频)」。

### 每做完一个：一个参考分

每数到一个 rep，界面上给一个 0–100 的分数与一个五级评级词（需改进 / 及格 / 中 / 良 / 优）。
组末再给一个整组的分。**分数和它评的那批判定同生同灭** —— 换一组就清空，
而不是留在屏幕上等着配错。

**这是一个有意的偏离，必须读清楚再改。**

`docs/domain-layer-design.md` §6.1 把「打分（Score）」划给决策层，§7.3 第 11 项
（组级评级权重 `w_fault`、发生率-扣分曲线、五级切分）标题写的是「**禁止工程师填数**」。
所以 `FormScorer` 做的不是「实现了文档里的打分」，而是**把文档里那个公式的端侧近似
显式标成近似**：

- **`provisional` 由数据决定，不是写死的文案。** 权重未核定**或**所扣判定未核定，
  它就是 `true`，界面挂「阈值待核定 · 仅参考」角标。**权重一旦经体育专业核定，
  角标自己就没了**，不需要有人记得回来改字。随包发出的五个权重现在全是 `1.0` 占位值。
- **归一化**：实现的是 `100 × (1 − Σ(w_i × rate_i × severity_i) / Σw)`。
  字面套用文档公式，在权重全为 `1.0` 时总分只会落在 95–100 ——
  再糟的动作也是 95 分，那个数字没有意义。除以权重和之后 0–100 才拉得开，
  而权重合计为 100 时两者代数等价。
- **逐次评分要去重**：`evaluateRep` 不去重，`evaluateSet` 去重（同一次 reps 内
  同一个 code 只计一次）。逐次评分按 code 取最严重的那一次，口径才和组级一致 ——
  否则同一件事逐次扣一遍、组级再扣一遍。
- **`severity01` 缺失时按 1.0 算，不按 0 算。** 严重度是 `|delta| / span`
  的单调函数而 `span` 每条规则固定，所以组级 `FaultStat` 只有 `worstDelta`
  也能反推出组内最坏严重度。
- **切点读表不写死在代码里**：五级怎么切来自 `squat.form_score_rating_breakpoints`，
  权重来自由 `squat.fault_weight.*`。表里改了，分数跟着改。

界面侧的配套纪律在 `ui/score_badge.dart`：**五级五色，但没有红色。**
一个未核定的分数不该长着判决书的样子。

测试分两层：`test/app/form_score_test.dart` 用一张自造的权重表（4/3/2/1/1）
测公式与口径，另有单独三条读**随包发出的那一份真实阈值表**，其中一条钉住
「权重还全是待核定的」—— 核定之后那条会红，reason 里写了该怎么改。

### 三个容易踩的点

**机位是 45° 斜机位，正对镜头会被拦。** 这不是产品偏好，是数学：
正对镜头时膝盖的弯曲在画面上几乎不改变投影角度，状态机会永远停在站立 ——
**计数恒为 0，而且不报任何错**。所以门禁把正位当成必须拦住的项，
拦不住的代价是一屏没有意义的数字。

**管线只保最新帧。** 推理比取帧慢是常态，排队处理会让延迟无限增长：
人已经站起来了，画面还在播三秒前的下蹲。丢帧率因此可能很高，那是正常的。

**一块面板的入参来自两个 `ValueNotifier` 时，两个都要订。** 深蹲页有两个源：
`session.view`（会话快照，10 Hz）与 `_pipeline.status`（相机状态）。
**读 `.value` 不算订阅** —— 在一个只订了 `session.view` 的
`ValueListenableBuilder` 里读 `_pipeline.status.value`，相机起来这件事不会触发
任何重建。真机上的症状是自检横幅一直停在「正在启动相机…」，直到有人走进画面、
会话发了第一份快照才跳过去 —— **而那时候横幅本来就该消失了**，
所以它是「一直错到不再需要它为止」，靠肉眼看很难发现。
（已在 `_panelBody` 里修掉，那边有完整注释。加新面板时照着那条规矩来。）

**阈值表 74 条全部是 `pending_review`。** 每条判定都只作提示、不驱动扣分，
界面上挂「待核定 · 仅提示」角标。措辞的降调是证据强度决定的，不是审美
（见 `lib/app/fault_presentation.dart` 的模块注释）—— 改文案之前先读阈值表里那条的 `_note`。

## 横屏与方向

五个动作**进练习页先锁横屏**：立定跳远、仰卧起坐、坐位体前屈、俯卧撑、平板支撑
（`ActionSpec.requiresLandscape`）。判据不是「品类」而是**几何**：这几项在做动作时
身体是**横着铺开**的（跳远往前往外、其余四项人整个躺在地上或坐着把上身折出去），
而竖直画面高而窄，横着的人必然被切掉两端 —— 头与脚各少一截，
门禁会报「身体贴到画面边上了」，用户按提示后退，人就更小。

**核心不是那一层引导，是相机旋转。** 管线原先只在 `start()` 时从
`camera.sensorOrientation` 推一次旋转角，而 `sensorOrientation` 是相对**机身**固定的
常数 —— 手机物理横过来 90° 之后它不再成立，而管线**从不重算**。后果是横屏下预览转了、
送进 ML Kit 的角不转：骨架躺倒，`PoseFrame` 相对重力歪 90°，而下游的站位判定与状态机
都假定「图像是正的」。所以 `platform/video_rotation.dart` 把这个角变成
**每帧按当前设备方向算**的函数，并且**逐字镜像**插件的
`DeviceOrientationManager.getVideoOrientation()`（后摄
`(angle + sensorOrientation) % 360`、前摄 `angle *= -1`，文件头写了镜像自哪个文件哪一行）。
镜像而不是自己推的理由：预览与骨架**共用同一个角**，只要同源，横竖屏下都必然贴合；
自己推一份出来，两边就会在某一个方向上悄悄差 90°。

**方向的单一主人是 `platform/orientation.dart`**，而它只有一个调用者：`main.dart`。
`main.dart` 把 `_stage` 的四处直接赋值收归一处，按
「练习页且报告没出来 → `practice`，其余一切 → `portrait`」算。
**报告态是练习页内部的子状态，不是 `_Stage`** —— 报告由 `SquatPage` 渲染，
「再来一组 / 重新标定」会从报告回到相机，只按 `_Stage` 判的话，从报告点「再来一组」
会把屏幕留在竖屏、而相机已经起来了。所以 `SquatPage` 把 `_showingReport` 的翻转
上报给 `main.dart`，**单主人不破**。

- **锁的是一个确定的横方向，不依赖手机的「自动旋转」开关。** 关了它的同学也不能卡在
  引导页，所以 `practice` 用的是**单元素**列表而不是 `DeviceOrientation` 全给。
  代价：只能朝一边横。**引导图上那个箭头必须与锁的那个方向一致** ——
  对不上就是用户照着转反而更歪。`landscapeLeft` 这个名字与实际朝向的对应要真机看一眼。
- **引导不能用 `MediaQuery.orientation` 当门。** 方向锁生效之后，显示方向**立刻**
  就是横的，而插件取方向用的是 `getDisplay().getRotation()`（显示方向，不是传感器）——
  **「用户有没有真的转过来」在代码里读不出来**。所以它是一个用户自己确认的一次性步骤：
  浮层盖在跑着的相机上（压暗），按「已经横过来了」之后才放行「立即开始」、
  自动倒计时与语音倒计时（三件事都要挡住，只挡按钮的话自动倒计时会把这一屏跳过去）。
- **横屏之后「离得远不远」的判据必须与方向无关。** 它取的是身体包围盒两个跨度里
  **较大的那个**（`camera_position_check.dart`）。转正图是宽大于高：站着的人若只按
  高度占比会被判成「离得远」，横躺着的人若只按高度占比则反过来偏小 ——
  两种误报都指向一个并不存在的距离问题。对竖屏既有动作**零行为改动**
  （站着的人高远大于宽），`camera_position_check_test.dart` 是这一步的回归网。
- **练习页的面板高度在横屏下要放宽**（`_overlay` 里那个系数），否则
  `PositionChecklist`（四行 + banner）与 `CountingHud` 会被挤到看不全。
- **`ActionSpec.isLyingDown` 那个字段已经删掉。** 它原来是「躺着的动作取横向跨度」
  的分叉；判据改成方向无关之后，它谁都不读了。按姿势分叉在这一层本来也不成立 ——
  门禁拿不到「用户现在是什么姿势」，分叉只能靠调用方传进来的一个常量，
  常量错了没有任何东西会报。
- **Android 16（API 36）且屏宽 ≥ 600dp 时系统会忽略方向锁**（Flutter 文档明写）。
  手机不受影响，**平板会**：横屏动作在平板上仍可能是竖着的画面。
- **待办：面板改成右侧一列（预览占左侧）。** 那是横屏下明显更好的版式，
  但它是一次独立的版式改版（`squat_page.dart` 的整套布局 + 两个面板的宽度假设），
  这一轮只放宽了高度，没有重排版面。

## 契约模型是手写的 —— 一处有意的偏离

`shared/contracts/` 下的两份 JSON Schema 由服务端的 Pydantic 定义自动导出，
通常的做法是用 `json_serializable` 或 `quicktype` 生成 Dart 模型。**这里没有这么做**，
`lib/app/decision_request.dart` 是手写的。

生成解决的是**作者手误**（漏个字段、漏条约束）。而这个接缝真正的风险是**两侧漂移**：
服务端改了字段端侧还在发旧的、端侧换了单位服务端没跟上 —— 生成出来的模型对此
一无所知，它只保证「照着这份 schema 没抄错」。

所以保证放在**跨语言 fixture** 上：`shared/fixtures/decision_request_conformance.json`
由 Python 侧生成期望请求，Dart 侧跑出同一份来逐字段比对
（`test/app/decision_request_conformance_test.dart`）。代价是契约升版时要手动改这个
文件；收益是它能被注释、能被测试逐字段锁住，而生成的代码两样都做不到。

**这也意味着 `decision_schema_version` 的改动必须与 `server/app/contracts.py` 的
`SCHEMA_VERSION` 同时发生。** 契约本身改了要重新导出 schema：

```bash
cd server && python -m tools.export_schema
```

## 隐私边界：只传特征，不传视频

未成年人影像属敏感个人信息。端侧算完特征后只上传结构化 JSON，**视频帧不出设备**：
姿态推理跑在手机上（ML Kit），发出去的只有关节坐标算出来的角度、次数与错误码
（字段见 `shared/contracts/decision_request.schema.json`），服务端拿不到任何一帧画面。

注意这条边界的准确含义：它约束的是**传什么**，而不是**传不传**。
主清单里已经声明了 `INTERNET`（组末那一次「分析这一组」要用），
它的注释里写的也是这句话 —— 别把它读成一张「不联网」的承诺。

**清单里的两条网络配置是会被真机卡住的，别只按「大概能过」来配**：

- `INTERNET` 权限：**debug / profile 清单里本来就有**（Flutter 模板自带，给热重载用），
  所以「debug 通、release 不通」是个真陷阱。
- `android:networkSecurityConfig`（`res/xml/network_security_config.xml`）：
  Android 9 起默认禁止明文流量，而决策服务是局域网上的明文 HTTP。
  不配的话，真机上的表现是连接直接失败 —— 与「服务没起」长得一模一样。

## 分析这一组

做完一组 → 报告页底部展开「分析这一组」→ 核对四项资料（**已按「我的资料」预填**，
在这里改只影响这一次）→ 点「分析这一组」→ 读一份中文报告。
请求与响应、失败文案、口径声明分别在这几个文件里：

| 关心的事 | 看哪儿 |
|---|---|
| 报告页整页长什么样 | `lib/ui/set_report_view.dart` |
| 发出去的是什么 | `lib/app/decision_request.dart` |
| 读回来的是什么（含字段级报错） | `lib/app/decision_response.dart` |
| 报告里说了什么（降调、证据 join、口径声明） | `lib/app/decision_report.dart` |
| 排版 | `lib/ui/analysis_report.dart` |
| 地址、失败分类、每种失败该说什么 | `lib/app/decision_submission.dart` |
| 真正发请求的那一处 | `lib/platform/decide_client.dart` |

**服务端地址默认是 `http://127.0.0.1:8080`**，演示走 USB 转发：

```bash
cd server && python -m app.api      # 另开一个终端
adb reverse tcp:8080 tcp:8080       # 手机上的 127.0.0.1:8080 → 笔记本的回环
```

这样地址与 WiFi 无关、不必把服务暴露在局域网、也不必配 key（非回环才强制）。
面板里的地址与密钥只在内存里，**不落盘**：上次那个 IP 现场很可能已经变了，
而一个看起来填好了的地址会让人先怀疑服务、后怀疑地址。**这一条与「我的资料」不搭车** ——
年龄会从档案预填，地址不会，两者的理由本来就不一样。

要在打正式包时换默认地址：

```bash
flutter build apk --release --target-platform android-arm64 \
  --dart-define=VITALTEEN_API_BASE=http://192.168.1.7:8080 \
  --dart-define=VITALTEEN_API_KEY=...
```
