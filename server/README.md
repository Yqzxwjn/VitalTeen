# server/ · 决策服务

**当前状态：实现与测试完整；但方案库与评分都处于「待核定」状态 —— 那是设计使然，不是没做完。**

手机端把**结构化特征与规则判定**传上来（不是视频，也不是关键点），这里调用 Laya
决策模型做三种判断，从矫正方案库中择优，产出面向用户的文案与报告。

**它不做什么**：不接触像素、不算几何量、不发明阈值、不做医学诊断。边界见
[docs/domain-layer-design.md](../docs/domain-layer-design.md) §6.1。

## 分层

```
server/
├── app/
│   ├── contracts.py   三方共同遵守的请求/响应契约（Pydantic，可导出 JSON Schema）
│   ├── state.py       把结构化请求转成 Laya 能读的文本 ← 全架构最关键的一次转换
│   ├── laya.py        Laya 客户端，编码了三条来自实测的防御
│   ├── service.py     决策编排：质量门 → 状态构造 → 调用模型 → 方案择优
│   ├── plans.py       矫正方案库（12 条种子方案，当前全部 draft）
│   ├── taxonomy.py    错误码 → 中文名
│   ├── adapter.py     领域层 → 契约的适配器（两个包唯一的接缝）
│   └── api.py         Flask 接口层
├── tools/                 导出物与跨语言 fixture —— 全是「改完要重跑」的
│   ├── export_schema.py            导出 JSON Schema 到 shared/contracts/
│   ├── export_plans.py             导出方案库到 shared/plans/
│   ├── export_rule_settings.py     导出 DecisionSettings 到 shared/decision/
│   ├── build_request_fixture.py    生成请求一致性向量
│   └── build_response_fixture.py   生成响应一致性向量（13 个场景，端侧靠它锁住本机判定）
└── tests/
```

## 跑起来

```bash
cd server
python -m pytest tests/ -q
python -m tools.export_schema --check          # 校验 schema 与契约同步
VITALTEEN_HOST=127.0.0.1 python -m app.api     # 默认 :8080
```

**手机连它走 USB 转发，不走局域网**：

```bash
adb reverse tcp:8080 tcp:8080     # 手机上的 127.0.0.1:8080 → 这台机器的回环
```

于是服务照旧只绑 `127.0.0.1`、不必配 `VITALTEEN_API_KEY`（非回环才强制），
而地址与现场 WiFi 无关 —— 演示场地换个路由器不用改任何配置。
端侧那边在 `app/README.md` 的「分析这一组」一节。

### 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `VITALTEEN_HOST` | `127.0.0.1` | 监听地址 |
| `VITALTEEN_PORT` | `8080` | 端口 |
| `VITALTEEN_API_KEY` | 无 | 绑非回环地址时**必须**配置，否则拒绝启动 |
| `LAYA_BASE_URL` | `http://127.0.0.1:8000` | laya-serve 地址 |
| `LAYA_API_KEY` | 无 | 指向非回环地址时**必须**配置 |
| `LAYA_TIMEOUT_S` | `5.0` | 单次决策超时 |
| `LAYA_OPTIONS_FIELD` | `options` | 候选字段名。Laya 改过名（`options` → `criteria`），**改这里而不是改代码** |

### ⚠️ 不要重复 laya-serve 的错误

调研发现 `laya-serve` 出厂监听 `0.0.0.0:8000` 且**不带任何鉴权** —— 局域网内任何人
都能调用它。本服务在客户端一侧已经拒绝过「指向非回环地址却不给 API key」的配置，
自己的接口层当然不能犯同样的毛病：

- 默认只绑 `127.0.0.1`
- 绑非回环地址时**必须**配 `VITALTEEN_API_KEY`，否则**拒绝启动**。这是启动期的检查，
  不是运行期的 —— 一个暴露在局域网上、还会返回未成年人身体数据的服务，
  不能等到被人访问了才发现
- 配了 key 之后 `/v1/decide` 需要 `Authorization: Bearer <key>`

`/health` 不要求鉴权：探活接口是给监控用的，加鉴权只会让它们没法工作，
而它不返回任何用户数据。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 探活。`?deep=1` 时额外探测 Laya 是否可达 —— 默认**不做**：一个会卡住的健康检查比没有健康检查更糟 |
| POST | `/v1/decide` | 决策。`?equipment=弹力带` 可重复传，声明可用器材 |

请求体校验失败返回 **400 且带逐字段错误**，端侧能直接定位 ——
这是把校验放在入口而不是业务逻辑里的全部意义。

## 契约里几条不显眼但重要的约束

- **`schema_version` 与 `thresholds_version` 都必填，刻意不给默认值。** 给了默认值，
  一个陈旧的客户端漏传时会被静默当作「当前版本」处理 —— 而它很可能正是版本不匹配的
  那一个。没有 `thresholds_version`，历史决策就无法复现，因为阈值已经升版了。
- **未知字段一律拒绝**（`extra="forbid"`）。静默忽略会让「端侧发了新字段、服务端还在
  用旧逻辑」这种不一致一直藏着，直到某个结果明显不对才被发现。
- **`candidates` 上限 20**，写进校验也写进 JSON Schema。Laya 在选项数超过约 20 后准确率
  急剧下降（第三方基准：Banking77 的 77 标签任务仅 0.425，而 Jev 为 0.870）——
  这是评估结论，不是保守估计。
- **候选集是封闭的**：决策层只能从候选里挑，不得发明候选之外的错误码。这是「决策层
  不做像素级识别」这条职责边界的执行方式 —— 如果它可以凭空发明一个错误类型，
  它就不再是在做判断，而是在做检测。
- **`status=abstain` 必须说明原因**，且 `status=ok` 时不得带原因。
  宁可弃权也不编造确定性。
- **`primary_fault` 必须在 `faults` 里** —— 有校验器强制，不是约定。
- **只要调用了 Laya，`meta.shuffled` 就必须为 True。** Laya 存在位置偏差
  （曾有「50 道多选题有 46 道选 A」的报告），不打乱就无法排除顺序效应。

## 喂给模型的文本：这一层最容易被做错

Laya 看不到视频、看不到关键点、看不到任何图像 —— 它对用户动作的**全部认知**，
就是 `state.py` 产出的那段文本。写得含糊它就判不准；写得太长它会静默截断。
三条写作原则：

1. **只陈述测量，不预先下结论。** 写的是「最深膝角 92 度」「合格线 95 度」，
   不是「深度不足」。把结论和证据一起喂进去，等于替模型想好了答案又让它
   「确认一下」—— 那样测出来的不是模型的判断力，而是它对输入的顺从程度。
2. **但候选集要如实给出**，因为这划定了判断的边界（见上文封闭性那条）。
3. **上下文是判断依据，不是装饰。** 14 岁和 18 岁的训练剂量不同；
   侧拍机位下膝内扣根本不可判。

**超长输入必须在构造侧拦住。** 多语言权重的上下文是 1024 token，
`MAX_STATE_CHARS = 800` 是留给它的安全余量。超了 Laya 会**静默截断**，
而截断会丢掉末尾信息（实测中截断方向会显著改变答案）。超长时走
`build_state_lenient` 逐级降级 —— 先丢逐次明细，再丢单项组级指标 ——
而不是把超长内容发出去。

## 方案库：内容与剂量是两回事

- **动作与机制**来自运动科学文献，每条方案带 `evidence_refs`
  （例如「动态膝外翻与髋外展/外旋肌力不足相关，故以髋周激活与强化为主」）
- **组次剂量**（几组、几次、每周几次、持续几周）属于**待体育专业成员核定**的内容。
  本项目不编造这类数字 —— 一个来源不明却看似专业的「3 组 × 12 次」，
  青少年照着练出了问题，责任是无法推脱的

所以 `Dosage` 的每个字段都可以是 `None`，含义是**尚未核定**，而不是「不需要」；
`describe()` 会如实输出「剂量待体育专业成员核定」。**任何渲染路径都不能因为字段为空
就省略整句话** —— 那会让用户以为这个动作没有剂量要求。

方案有 `status`：`draft`（剂量待核定，不用于决策）/ `active` / `deprecated`。
状态为 `active` 但没有 `evidence_refs` 会在**构造时直接抛异常** ——
没有文献支撑的方案不能作为建议推送给用户。

**当前 12 条种子方案全部是 `draft`**，因此会走「未核定」回退路径并在剂量说明里标注。
这是诚实的状态，不是没做完 —— 与阈值表里 74 条全部 `pending_review` 是同一套思路：
**未核定的内容可以驱动「研究」，但不能驱动「建议」。**

**器材语义要说清楚。** 墙、地面、椅子这类随处可见的东西**不算器材** —— 把它们列进去
会让「家里没器材」的学生被排除在所有地面动作之外，而他们完全能做，只是需要一块空地。
默认 `available_equipment=()`（假定徒手）。目前只有**弹力带**属于需要专门购买的一项。

## 断网也能演示：降级路径会自我标识

Laya 不可达（断网、服务没起来、超时）时走规则兜底：用组级统计直接推出主问题与严重度，
用方案库的确定性排序选练习。答辩现场故意演示一次断网降级，反而是加分项。

但它产出的结论**不是模型的判断**，因此 `meta.decision_model_version` 会写成
`rule-only`。少了这个标识，事后没人分得清某个建议来自模型还是来自规则 ——
而这两者的可信度、可解释性、能通过的验证方式完全不同。

**评分同理。** 正式的组级评级需要各错误码的权重与发生率-扣分曲线，而这些属于待核定
阈值（设计文档 §7.3 第 11 条）。在核定之前，服务基于**测量到的偏离幅度**算一个参考分，
并把 `Scores.provisional` 置为 `True`。用一个自己编的权重冒充专业标准，
是这类系统最不该犯的错。

### 这条路径现在有两份实现

端侧（`app/lib/app/local_decision.dart`）在**连不上服务时**会自己算一份同样的响应，
所以这条规则路径的行为与它依赖的那几个工程参数都被跨语言锁住了：

- 参数（`DecisionSettings`）→ `python -m tools.export_rule_settings` → `shared/decision/`；
- 行为与文案 → `python -m tools.build_response_fixture` 生成的 13 个场景，
  其中每个都压住这条路的一条分支（质量门三条、主问题并列、未知 vs 零、半偶舍入、
  统计与候选集不相交、器材与年龄过滤……）。

**改这一段的任何一处，两条 `--check` 都会红，而端侧会跟着红。** 那是有意的：
两份实现漂移不会报错，只会让同一个学生、同一组动作，断网与联网得到两份不同的报告。

## Laya 客户端编码的三条防御

1. **必须用多语言权重**（`laya-multilingual`）。英文版 `laya` 对中文输入基本失效 ——
   第三方实测中文准确率 **47.7%**，而英文短题 95.8%。选权重是 `laya-serve` 的
   `LAYA_MODELS` 的职责，但这条约束写在这里，因为选错的代价是
   「系统看起来很确定地在胡说」。
2. **候选顺序必须打乱**，见上文。
3. **必须容忍字段名漂移。** Laya 开源后两周内从 0.1.1 迭代到 0.3.x，决策问题的选项
   字段由 `options` 改成 `criteria`。本模块因此**请求侧可配置、响应侧宽容解析** ——
   请求格式在我们自己手里，响应格式在厂商手里。字段名这类不稳定的东西集中在一个
   文件里，不扩散到决策服务与契约层。

`LayaConfigError` **刻意不继承可降级的异常** —— 配置错误不会因为重试而变好。
把它混进「模型暂时不可用」的降级路径里，会让一个配置疏漏表现为「系统一直在用兜底
逻辑」，而且没人会发现。
